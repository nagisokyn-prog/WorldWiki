# 🧪 ПРАВИЛО 04: ОБЯЗАТЕЛЬНЫЙ СТАНДАРТ ТЕСТИРОВАНИЯ (TDD & BRANCH COVERAGE)

> **ОБЛАСТЬ ДЕЙСТВИЯ**: Фронтенд (Vitest) и Бэкенд (Cargo Test).
> **СТАТУС**: КРИТИЧЕСКИЙ (Ни одна задача не принимается без тестов).

---

## 1. Фронтенд: Тест на каждый Composable-хук

* Для каждого файла `use<Feature>.ts` **ОБЯЗАТЕЛЕН** парный файл тестов `use<Feature>.spec.ts` (или в папке `__tests__/`).
* Тестируются все возвращаемые свойства, реактивные эффекты и методы.

---

## 2. Бэкенд: Тест на каждый Use Case

* Для каждого сценария `application/*/*.rs` пишется Unit-тест с Mock/Fake реализацией портов (без поднятия Tauri и реальной БД).
* Тестируется чистая логика домена, валидация и генерация событий.

---

## 3. Матрица покрытия ветвлений (Branch Coverage)

Каждый набор тестов обязан покрывать 4 обязательных сценария:

| Сценарий | Что проверяется |
|---|---|
| 🟢 **Success Path** | Штатная загрузка, сохранение, корректность структуры возвращаемых данных. |
| 🔴 **Error & Rollback** | Откат оптимистичного стейта при сбое сети/бэкенда, корректная обработка `ApplicationError`. |
| ⚠️ **Edge Cases** | Пустые массивы, `null`/`undefined` аргументы, превышение лимитов символов, нулевые ID. |
| ⏱️ **Async & Cancellation** | Отмена таймеров Debounce при `unmounted`, отмена тяжелой задачи через `CancellationToken`. |

---

## 4. Команды запуска проверок

```bash
# Тесты фронтенда
pnpm --filter @worldwiki/spa test
pnpm --filter @worldwiki/components test

# Тесты бэкенда
cargo test --workspace
```
