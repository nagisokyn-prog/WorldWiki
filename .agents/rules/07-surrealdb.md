# 🗄️ ПРАВИЛО 07: СТАНДАРТ SURREALDB (v3.2+)

> **ОБЛАСТЬ ДЕЙСТВИЯ**: Все схемы (`logic/schema/**`), миграции и Rust-адаптеры к SurrealDB.
> **СТАТУС**: КРИТИЧЕСКИЙ (Автоматический аудит через Cerberus: правила `SDB-001..SDB-008`).

---

## 1. Реестр Инвариантов SurrealDB

Все правила работы с БД проверяются компилятором и Cerberus (`cargo cerberus check`):

1. **`SDB-001` — Строгая схема**: Все таблицы строго `SCHEMAFULL`. Динамические поля (`FLEXIBLE`) разрешены только для `attributes` и `embeddings`.
2. **`SDB-002` — Идемпотентность DDL**: Все DDL-выражения (`DEFINE TABLE/FIELD/INDEX/EVENT/ANALYZER`) обязаны содержать `OVERWRITE`.
3. **`SDB-003` — 100% Параметризация**: Запрещена строковая конкатенация SQL. Все параметры передаются **СТРОГО** через `.bind()`.
4. **`SDB-004` — Защита от раздувания векторов**: Векторы эмбеддингов (`embeddings.*`) **ЗАПРЕЩЕНО** сохранять в таблицы ревизий/снимков.
5. **`SDB-005` — Изоляция типов**: Типы `surrealdb::sql::Thing` и `surrealdb::Value` изолированы внутри `infrastructure` и не проникают в `domain` или `application`.
6. **`SDB-006` — FK-индексы**: Все внешние связи (`project_id`, `*_id`) обязаны иметь явный B-Tree индекс `FIELDS`.
7. **`SDB-007` — Атомарные функции**: Сложные графовые и RAG-выборки выполняются через хранимые функции `fn::*`.
8. **`SDB-008` — Каскад в DDL**: Удаление дочерних деревьев реализуется через DDL-события (`EVENT ... WHEN $event = "DELETE"`).

> Для карточек правил используйте: `cargo cerberus rule explain SDB-001` (или `SDB-002` .. `SDB-008`).

## 2. Модульная структура схемы

Схемы разделены на две строго изолированные директории:

```
logic/schema/
├── no_ai/                          # 🟢 Чистое ядро (Base Edition)
│   ├── 00_analyzers.surql          # Токенизаторы fulltext поиска (ru_en_analyzer)
│   ├── 01_tables.surql             # Таблицы и поля ядра (проекты, главы, сущности, таймлайн)
│   ├── 02_indexes.surql            # B-Tree, FK и BM25 индексы
│   └── 03_events.surql             # Каскады и триггеры снимков ревизий
└── ai/                             # 🧠 ИИ-пространство (Ultra Edition)
    ├── 01_workspace_tables.surql   # Чаты, профили, память, навыки
    ├── 02_web_research_tables.surql# Веб-кэш и факты
    ├── 03_embeddings_hnsw.surql    # HNSW векторные индексы
    ├── 04_indexes.surql            # B-Tree/BM25 для ИИ-таблиц
    ├── 05_events.surql             # Каскады чатов
    └── 06_functions.surql          # RAG-функции (fn::gather_rag_bundle)
```

## 3. Стандарты DTO и IPC

1. **Record ID**: Сериализуются в строки `"таблица:id"`.
2. **Даты**: Сериализуются в стандартный ISO-8601 (`"2026-09-20T12:00:00Z"`).
3. **Реактивность UI**: Мутации в БД публикуют доменные события (`EventPublisherPort`), а фронтенд обновляет Pinia Store без F5.
