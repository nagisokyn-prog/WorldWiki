# ⚡ ПРАВИЛО 08: ПРОИЗВОДИТЕЛЬНОСТЬ И РЕАКТИВНАЯ ЦЕЛОСТНОСТЬ (CERBERUS PERF)

> **СТАТУС**: КРИТИЧЕСКИЙ (Автоматический контроль через `cerberus-sfc check` и `cargo cerberus check`).

Все правила производительности и утечек памяти проверяются Cerberus на уровне AST:

1. **Реактивность и память (`PERF-001`, `PERF-002`, `PERF-005`)**:
   * Для тяжелых структур данных (AST, логи, большие списки) — использовать `shallowRef` + `triggerRef`, `markRaw` и `Object.freeze`.
   * Запрещены глубокие каскадные `watch(..., { deep: true })` без ограничения глубины.
   * Экземпляры внешних библиотек (Monaco, Tiptap, Canvas, Three.js) оборачиваются строго в `markRaw`.

2. **DOM и Layout (`PERF-004`, `PERF-DOM-001`)**:
   * Запрещены некэшируемые вызовы методов в шаблонах — выносить в `computed`.
   * Модалки, табы и тяжелые блоки монтируются через `v-if` (Lazy Mount), а не `v-show`.
   * Запрещен Layout Thrashing (чередование чтения геометрии и записи стилей в цикле).

3. **Симметричная очистка ресурсов (`LEAK-001`, `FE-RAII-001`)**:
   * Все слушатели Tauri IPC (`listen`), каналы (`Channel.onmessage`), таймеры (`setInterval`) и глобальные DOM-слушатели **ОБЯЗАНЫ** очищаться в `onUnmounted`.

> Для просмотра подробных примеров и карточек ремедиации используйте:
> `cargo cerberus rule explain PERF-001` (или `PERF-002`, `LEAK-001`, `VUE-007`).
