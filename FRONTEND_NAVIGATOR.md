# 🧭 Руководство по Архитектуре Фронтенда (Frontend & FSD Navigator)

> **Для ревьюера**: Этот документ подробно раскрывает инженерные стандарты, принципы взрослой архитектуры (**Feature-Sliced Design**), организацию TypeScript-слоев, систему стилей и инструментов контроля качества в проекте **WorldWiki**.

---

## 🏛️ 1. Философия Архитектуры: Почему FSD, а не «Folder-by-Type»

Большинство студенческих и pet-проектов строятся по наивному принципу **«папки по типам файлов»** (`/components`, `/hooks`, `/types`, `/utils`, `/api`). 

### 💥 Почему «Folder-by-Type» умирает при росте проекта:
1. **Каша зависимостей (Spaghetti Imports)**: Компонент из `/components` может импортировать хук из `/hooks`, который дергает тип из `/types`, который импортирует другой компонент. Границы модулей размываются.
2. **Сложность рефакторинга**: Чтобы удалить или переписать одну фичу (например, *«Сюжетные арки»*), приходится вычищать 6 разных папок по всему проекту, боясь сломать что-то чужое.
3. **«Божественные компоненты» (God Components)**: В классическом подходе файл `ChapterEditor.vue` быстро разрастается до 2000+ строк, где перемешаны разметка, анимации, запросы к БД, бизнес-логика и CSS.

### 🌟 В чем сила Feature-Sliced Design (FSD) в WorldWiki:
FSD организует кодовую базу **по бизнес-ценности (фичам)**, а не по техническим типам файлов:
* **Высокая связность (High Cohesion)**: Всё, что нужно для работы конкретной фичи (верстка, хуки, типизация, тесты, стили), лежит в одном месте.
* **Слабая зацепленность (Loose Coupling)**: Фичи не знают о внутреннем устройстве друг друга и общаются только через глобальные сторы (Pinia) или публичные контракты.
* **Масштабируемость**: Новая функциональность добавляется изолированным срезом (Slice), не создавая технического долга в существующих модулях.

## 🗺️ 2. Карта Слоёв Фронтенда (`apps/spa/src/ts/`)

Кодовая база фронтенда разделена на строгие архитектурные слои с правилом: **«Верхние слои могут импортировать нижние, но нижние НИКОГДА не импортируют верхние»**.

```
apps/spa/src/ts/
├── app/          # 🚀 Layer 1: Точка входа, Composition Root, плагины, роутер
├── features/     # 🧩 Layer 2: Бизнес-фичи приложения (FSD Slices)
├── composables/  # 🪝 Layer 3: Переиспользуемые кросс-фичевые хуки
├── stores/       # 🍍 Layer 4: Глобальное реактивное состояние (Pinia)
├── services/     # ⚙️ Layer 5: Системные сервисы, AST-трансформеры, Tauri IPC фасад
├── shared/       # 🧱 Layer 6: Общие переиспользуемые UI-компоненты
├── utils/        # 🛠️ Layer 7: Чистые функции и математика (Pure utilities)
└── types/        # 🏷️ Layer 8: Глобальные DTO и сгенерированные Rust-типы
```

### 📂 Подробное назначение каждой директории:

#### 1. `app/` (Composition Root & Инициализация)
Точка сборки всего приложения.
* Инициализация экземпляра Vue 3 (`main.ts`, `app.ts`).
* Регистрация глобальных плагинов: Pinia, Vue Router, Vue I18n, Motion.
* Настройка тем оформления, провайдеров и глобальных обработчиков ошибок.

#### 2. `features/` (Бизнес-модули / FSD Slices)
Ядро приложения. Каждая фича полностью автономна:
* `chapters/` — редактор рукописей (Tiptap v3), дерево глав (`ChapterTree`), панель блоков/сцен (`PromisesPanel`), канбан арок (`StoryArcs`).
* `timeline/` — диегетическое время ($M_{\text{abs}}$), конструктор вымышленных календарей, фазы лун, погодные паттерны, `TimeAtlas`.
* `entities/` — карточки персонажей/локаций, визуальный граф связей на Canvas (`GraphWeb`), хронология путешествия (`CharacterJourney`).
* `ai/` — AI-ассистент: ветвящееся дерево чата, контекстные вырезки, цитирование текста, вызов функций (Tool Calling).
* `documents/` — процессоры академических и художественных документов, экспорт в DOCX, PDF, EPUB, FB2.
* `schemas/` — визуальный конструктор типов сущностей и динамических полей (`SchemaEditor`).
* `shell/` — каркас интерфейса, запуск проектов (`ProjectLauncher`), системные модалки.

#### 3. `composables/` (Кросс-фичевые хуки)
Хуки общего назначения, не привязанные к конкретной бизнес-фиче:
* Управление жизненным циклом и клавиатурными шорткатами (`useKeyboardShortcuts`).
* Асинхронные запросы и кэширование TanStack Vue Query (`queries/`).
* Управление всплывающими подсказками, тостами и диалогами.

#### 4. `stores/` (Глобальное состояние Pinia)
Единый источник правды для доменных данных приложения:
* `chapters.store.ts` — активная глава, выделенный нарративный блок, дерево структуры.
* `story_arcs.store.ts` — реестр сюжетных арок и их связи с главами/сценами.
* `calendar.store.ts` — календари текущего проекта, синхронизация диегетических дат.
* `entity.store.ts` — база персонажей, локаций, фракций и связей.

#### 5. `services/` (Низкоуровневые сервисы и адаптеры)
Слой абстракции над системными API и сложными преобразованиями:
* `api.client.ts` — **главный фасад бэкенда**: 100% типизированный клиент к командам Tauri IPC (`invoke(...)`). Изолирует фронтенд от Rust-деталей.
* `document/ast/` — адаптеры **Semantic AST**: двунаправленная конвертация между Tiptap JSON и типизированным AST рукописи (`ASTAdapter.ts`).
* `document/layout/` — математический движок постраничной верстки (`LayoutEngineService.ts`).

#### 6. `shared/` (Переиспользуемый UI низкого уровня)
Базовые UI-блоки, специфичные для предметной области приложения:
* `UniversalDatePicker` — пикер дат для вымышленных миров с произвольным количеством месяцев и дней.
* `RelationshipBlock` — блок выбора и конфигурации взаимосвязей между сущностями.
* `ManuscriptPointPicker` — компонент точной навигации по рукописи (Глава $\to$ Абзац).

#### 7. `utils/` (Чистые функции / Pure Helpers)
Функции без побочных эффектов и реактивности:
* Форматирование дат, математические преобразования временных шкал.
* Сравнение структур данных (`shell.dataMerge.ts`), хелперы для строк и DOM.
* Физика и параметры микро-анимаций (`ui.animations.ts`).

#### 8. `types/` (Типизация)
* `generated/` — типы, автоматически генерируемые из Rust-структур через `ts-rs` (`PlotPromise.ts`, `Chapter.ts` и т.д.). Гарантирует 100% соответствие контрактов фронтенда и бэкенда.
* Общие интерфейсы ответов, пагинации и базовых DTO.

## 🧩 3. Каноническая 4-компонентная анатомия модуля

Каждый UI-блок организуется строго по 4-файловой структуре:

```
MyFeature/
├── MyFeature.vue              # 🟢 Чистая декларативная верстка (без логики в script setup)
├── useMyFeature.ts            # 🧠 Вся логика: reactive state, computed, методы, API
├── MyFeature.model.ts         # 🏷️ Только TypeScript-интерфейсы: Props, Emits, DTO
└── useMyFeature.spec.ts       # 🧪 Обязательные Unit-тесты для Composable-хука (Vitest)
```

### 🔒 Почему это важно:
1. **Тестируемость без DOM**: Хук `useMyFeature.ts` можно протестировать в Vitest на 100% путей выполнения (успех, ошибка, краевые случаи) без рендеринга медленного виртуального DOM.
2. **Читаемость шаблона**: `.vue` файл содержит только понятный HTML/CSS-скелет и вызов хука `const { state, actions } = useMyFeature(...)`.
3. **Линейный поток данных**:
$$\text{Шаблон (.vue)} \longrightarrow \text{Хук (use*.ts)} \longrightarrow \text{Pinia Store} \longrightarrow \text{API Client (api.client.ts)} \longrightarrow \text{Tauri IPC (Rust)}$$

## 🎨 4. Архитектура CSS и Дизайн-Системы (`packages/resources/`)

В проекте **категорически запрещен хардкод цветов (`#fff`, `rgb(...)`) и прямое написание стилей внутри `<style>` в SFC**.

### 📁 Структура стилей (`packages/resources/src/styles/`):
```
packages/resources/src/styles/
├── tokens/             # 🎨 Токены дизайн-системы (CSS Custom Properties)
│   ├── theme-light.css # Светлая тема (--bg-surface, --text-main, --accent)
│   ├── theme-dark.css  # Тёмная тема
│   └── theme-glass.css # Стеклянная тема (Glassmorphism, backdrop-filter)
├── base/               # 📐 Базовые правила, сбросы (reset), шрифты
├── features/           # 🧱 Стили фичей (1:1 зеркалируют features фронтенда)
│   ├── chapters/       # PromisesPanel.css, ChapterArcTags.css, ArcBoard.css
│   ├── timeline/       # TimelinePanel.css, TimeAtlasModal.css
│   └── entities/       # EntityEditor.css, GraphWebView.css
└── components/         # 🔘 Стили переиспользуемых кнопок, дропдаунов, инпутов
```

### 💅 Как стили подключаются к компонентам:
Компоненты подключают внешние модульные таблицы стилей:
```html
<template>
  <div class="promise-card-arc-tags">...</div>
</template>

<script setup lang="ts">
// только логика и клей
</script>

<style scoped src="@worldwiki/resources/styles/features/chapters/PromiseCardArcTags.css"></style>
```

## 🛡️ 5. Линтеры и Архитектурный Файрвол (Cerberus)

Качество кода контролируется на уровне компилятора и автоматических чекеров:

1. **TypeScript (`vue-tsc -b`)**:
   * Строгий режим (`strict: true`, `noImplicitAny: true`).
   * Полный запрет на `any` и `@ts-ignore` без архитектурного обоснования.
2. **ESLint 9+ (Flat Config)**:
   * Проверка чистоты Vue 3 SFC шаблонов и неиспользуемых переменных.
3. **Cerberus Architectural Firewall (`cargo cerberus check` & `cerberus-sfc check`)**:
   * Контроль размера файлов (`ARCH-031`): компонент $\le 165$ строк, хук $\le 265$ строк.
   * Контроль чистоты CSS: запрет `transition: all`, запрет hex/rgb цветов, запрет тяжелых инлайн-стилей в SFC.
4. **Knip (`pnpm knip`)**:
   * Поиск битых импортов, неиспользуемых файлов и мертвых экспортов.

## 🚀 6. Полезные команды для ревьюера

```bash
# 1. Установка всех зависимостей монорепозитория
pnpm install

# 2. Строгая проверка типов во всех пакетах
pnpm typecheck

# 3. Запуск линтера кода
pnpm lint

# 4. Прогон модульных unit-тестов (Vitest)
pnpm test

# 5. Запуск комплексного архитектурного аудита Cerberus
cargo cerberus check --ci

# 6. Запуск SPA в режиме разработки
pnpm dev
```
