# Навык: Заполнение и Редактирование Сущностей (Entity Data Fill)

## 1. Назначение

Этот навык инструктирует ИИ-агента, как **правильно заполнять, обновлять и валидировать анкеты сущностей** через инструмент `entity_manage`.

Агент обязан строго соблюдать соответствие схемы типа сущности (`full_schema`), нормализовать неточные формулировки автора в канонические значения схемы и бережно сохранять неизмененные данные.

---

## 2. Железные Правила Заполнения

### 2.1. Нормализация Значений (Маппинг на `options.value`)
Авторы часто выражают мысли свободно и в разном роде/падеже (например: *«сделай, что Катя главная героиня»*, *«он маг»*, *«статус — жива»*).

* **ПРАВИЛО**: ИИ **ОБЯЗАН** сопоставить фразу автора со списком вариантов схемы и передать в `attributes` точный системный **`value`**, а не `label` и не авторскую фразу.

| Запрос автора | Поле в схеме (`options`) | Что ПРАВИЛЬНО записать | Что ОШИБОЧНО записать |
|---|---|---|---|
| *«Катя — главная героиня»* | `[{"value": "главный", "label": "Главный герой"}]` | `"роль_в_истории": "главный"` | ❌ `"Главный герой"`, ❌ `"главная героиня"` |
| *«Она сейчас жива»* | `[{"value": "жив", "label": "🟢 Жив"}]` | `"статус": "жив"` | ❌ `"🟢 Жив"`, ❌ `"жива"` |
| *«Служит в королевской гвардии»* | `[{"value": "гвардия", "label": "Королевская гвардия"}]` | `"фракция": "гвардия"` | ❌ `"Королевская гвардия"` |

---

### 2.2. Поле Фото (`type: "photo"`) — СТРОГИЙ ЗАПРЕТ
* 🛑 **ИИ НИКОГДА НЕ ЗАПОЛНЯЕТ ПОЛЕ ФОТО**:
  - Запрещено выдумывать ссылки на изображения, локальные пути или плейсхолдеры (например `https://...`, `/images/...`).
  - Поле `фото` предназначено **исключительно** для ручной загрузки автором файла в интерфейсе.
  - При создании сущности оставляй поле `фото: ""` пустым, а при обновлении — **никогда не затирай** уже загруженное автором фото.

---

### 2.3. Множественный выбор (`multiselect`)
Поля множественного выбора (`multiselect` и `tags`) всегда хранятся и передаются как **массив строк (`Array<string>`)**:

1. **Обычный multiselect с опциями**:
   ```json
   "черты_характера": ["храбрый", "импульсивный", "честный"]
   ```
2. **Multiselect со связью на сущности (`entityType: "organization"`)**:
   Передаются системные ID или точные имена связанных сущностей:
   ```json
   "союзные_фракции": ["organizations:shadow_court", "organizations:royal_guard"]
   ```
3. **Поле `теги` (`type: "tags"`)**:
   Ключевые слова в виде массива строк:
   ```json
   "теги": ["маг", "главный герой", "орден пламени"]
   ```

---

### 2.4. Двусторонние Отношения (`Двунаправленная связь`)
Отношения между сущностями (дружба, вражда, нейтралитет, подчинение) фиксируются через структуру базового шаблона связей:

```json
{
  "отношения": [
    {
      "целевая_сущность": "entities:char_vladimir",
      "тип_отношения": "союзник",
      "relationshipStates": [
        {
          "начальная_глава": {
            "volume_id": "volumes:vol_1",
            "chapter_id": "chapters:ch_3",
            "is_auto_extend": false
          },
          "конечная_глава": {
            "volume_id": "volumes:vol_1",
            "chapter_id": "chapters:ch_10",
            "is_auto_extend": true
          },
          "тип_связи": "крепкая дружба",
          "сила_отношений": 85,
          "описание_причина": "Вместе спасли деревню от набега гоблинов."
        }
      ]
    }
  ]
}
```

* **`сила_отношений`**: Шкала от `-100` (заклятый враг) до `+100` (абсолютная преданность / любовь). `0` — нейтралитет.
* **`is_auto_extend: true`**: Для конечной главы указывает, что отношение актуально по настоящее время сюжета.

### 2.6. Даты по Календарю Мира (`type: "calendar_datetime"`)
ИИ передает **ТОЛЬКО понятные календарные параметры**.

🛑 **КАТЕГОРИЧЕСКИЙ ЗАПРЕТ**: ИИ **НЕ ВЫЧИСЛЯЕТ** и **НЕ ПЕРЕДАЕТ** `absolute_minute`. Расчет абсолютной минуты выполняет математический движок `CalendarMath` на бэкенде/фронтенде.

```json
{
  "дата_рождения": {
    "calendar_id": "calendars:cal_main",
    "original_input": {
      "era_index": 0,
      "year": 1240,
      "month": 4,
      "day": 18,
      "hour": 12,
      "minute": 0
    }
  }
}
```
*Если точные часы/минуты неизвестны, `hour` и `minute` выставляются по умолчанию (`12:00`), либо передаются только `{ "year": 1240, "month": 4, "day": 18 }`.*

## 3. Процесс Вызова `entity_manage`

### Шаг 1: Инспекция схемы (если не уверен в полях)
Перед внесением сложных изменений вызови `entity_inspect(entity_id_or_name: "type:character")` для получения актуального `fill_guide` и списка допустимых `options`.

### Шаг 2: Формирование Payload
При обновлении (`action: "update"`):
```json
{
  "action": "update",
  "payload": {
    "id": "entities:char_katya",
    "name": "Катя",
    "type_key": "character",
    "description": "Главная героиня повести, маг воздуха.",
    "tags": ["маг", "главный герой"],
    "attributes": {
      "роль_в_истории": "главный",
      "статус": "жив",
      "прозвище": "Ветрокрылая"
    }
  }
}
```

### Шаг 3: Сохранение контекста
Не удаляй существующие записи в `эволюция_возраста`, `эволюция_занятий` или `отношения`, если автор попросил добавить новую запись или изменить одно конкретное свойство. Считывай текущее состояние и делай аккуратный merge.

---

## 4. Чек-лист Самопроверки для ИИ

- [ ] Все варианты `select` сопоставлены с каноническими `value` схемы (не `label`!).
- [ ] Поле `фото` не заполнено выдуманной ссылкой.
- [ ] `multiselect` и `теги` переданы массивами строк `[...]`.
- [ ] Точки рукописи содержат `volume_id`, `chapter_id` и `is_auto_extend`.
- [ ] Двусторонние связи содержат `целевая_сущность`, `тип_отношения` и `relationshipStates`.
- [ ] Существующие поля анкеты не затерты пустыми значениями.
