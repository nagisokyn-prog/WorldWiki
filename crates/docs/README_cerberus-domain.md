## 🌟 Назначение крейта

`cerberus-domain` инкапсулирует фундаментальные сущности, правила валидации, структуры данных, метрики и математические формулы всей системы Cerberus. Крейт является ядром гексагональной архитектуры и не зависит ни от каких других крейтов проекта или внешних SDK.

---

## 🛑 Архитектурный инвариант ARCH-001

> **КРИТИЧЕСКОЕ ТРЕБОВАНИЕ**: В крейте `cerberus-domain` **СТРОГО ЗАПРЕЩЕНЫ** любые внешние библиотеки ввода-вывода (I/O), сетевые клиенты (`reqwest`, `hyper`), базы данных (`surrealdb`), рантаймы (`tokio`), фреймворки (`tauri`), а также парсеры (`syn`, `walkdir`).
> 
> Единственные разрешенные зависимости — стандартная библиотека Rust `std`, базовая сериализация `serde` и чистый хэшер `sha2`.

## 📁 Пофайловая структура и ответственность

```
crates/cerberus-domain/src/
├── lib.rs            # 📚 Корневой модуль и реэкспорт доменного API
├── catalog.rs        # 📖 Офлайн-каталог документации правил (RuleCatalog, RuleDocEntry)
├── rules.rs          # 📜 Сущности Rule, Severity, Violation, Fingerprints
├── registry.rs       # 🏛️ Встроенный эталонный реестр правил (BuiltinRuleRegistry)
├── suppression.rs    # 🔐 Модель SuppressionRecord, подписи HMAC-SHA256
├── metrics.rs        # 📐 Метрики сложности AST, SLOC и расчет давления S_arch
├── layer.rs          # 🧱 Гексагональные слои и слои FSD, проверка направлений
├── tree.rs           # 🌳 Структура дерева компонентов (ComponentNode)
├── preset.rs         # 🎚️ Профили строгости правил (Strict, Recommended, Relaxed)
├── cluster.rs        # 🧠 Модель семантического кластера нарушений
├── sla.rs            # 📊 Конфигурация инженерного SLA (Recall, Precision, RSS)
├── path_utils.rs     # 🛠️ Кроссплатформенная нормализация путей файлов
└── traits.rs         # 🔌 Базовые доменные интерфейсы
```

### 1. [`lib.rs`](./src/lib.rs)
- **Ответственность**: Входная точка доменного ядра, декларация модулей и открытый экспорт типов.

### 2. [`rules.rs`](./src/rules.rs)
- **Ответственность**: Доменное представление архитектурного правила, зафиксированного нарушения и пороговых лимитов (`LimitsConfig`).
- **Ключевые типы**:
  - `Severity`: уровни строгости (`Allow`, `Warn`, `Deny`).
  - `Category`: категории правил (`Architecture`, `Frontend`, `Css`, `Taint`, `Async`, `Security`, `AI`, `ErrorHandling`, `Performance`, `Concurrency`, `Testability`).
  - `Rule`: описание правила (ID, имя, категория, severity по умолчанию, сообщение об ошибке, совет по исправлению `remediation`).
  - `LimitsConfig`: пороговые лимиты на SLOC (`max_sloc_warn`, `max_sloc_deny`), давление $S_{\text{arch}}$ (`max_pressure_warn`, `max_pressure_deny`) и жесткое количество функций на модуль (`max_functions_warn`, `max_functions_deny` — правило `ARCH-032`).
  - `Violation`: конкретное зафиксированное нарушение (ID правила, файл, строка, колонка, имя символа, фрагмент кода, отпечаток `fingerprint`).
- **Как работает `compute_fingerprint`**:
  - Принимает `rule_id`, `version`, `symbol` и `code_snippet`.
  - Удаляет незначимые пробелы и переносы строк из фрагмента кода (нормализация).
  - Вычисляет SHA-256 отпечаток:
    $$\text{Fingerprint} = \text{SHA256}(\text{rule\_id} \mathbin{\Vert} \text{version} \mathbin{\Vert} \text{symbol} \mathbin{\Vert} \text{normalized\_code})$$
  - Обеспечивает стабильность отпечатка даже при форматировании кода `rustfmt` или `prettier`.

### 3. [`registry.rs`](./src/registry.rs)
- **Ответственность**: Единый источник правды (Single Source of Truth) для встроенных правил Cerberus.
- **Как работает**:
  - Содержит каталог всех эталонных правил (`ARCH-001..ARCH-032`, `MOD-001`, `CQRS-001`, `EVT-001`, `VUE-001..VUE-009`, `CSS-001..CSS-006`, `DS-001..DS-003`, `CSS-PERF-001..005`, `SEC-001..009`, `ERR-001..005`, `CONC-002..008`, `AI-001..013`, `TEST-002..005`).
  - Поддерживает канонические алиасы (например, `arch/domain-purity` $\to$ `ARCH-001`, `code/max-functions` $\to$ `ARCH-032`).
  - Выполняет метод `validate_registered_rules(...)` для защиты от опечаток в пользовательских файлах конфигурации.

### 4. [`suppression.rs`](./src/suppression.rs)
- **Ответственность**: Доменная модель криптографического подавления нарушений.
- **Ключевые типы**:
  - `SuppressionRecord`: запись о подавлении (`rule_id`, `fingerprint`, `reason`, `author`, `created_at`, `expires_at`, `signature`).
- **Как работает**:
  - Формирует строку полезной нагрузки:
    $$\text{Payload} = \text{rule\_id} : \text{fingerprint} : \text{reason} : \text{author} : \text{expires\_timestamp}$$
  - Проверяет срок действия (TTL) записи: если текущее время больше `expires_at`, подавление считается недействительным.

### 5. [`metrics.rs`](./src/metrics.rs)
- **Ответственность**: Моделирование метрик сложности и архитектурного давления кодовой базы.
- **Ключевые типы**:
  - `AstComplexity`: количество функций ($N_{\text{functions}}$), цикломатическая сложность (Cyclomatic Complexity), максимальная глубина вложенности AST (Max Nesting Depth).
  - `SlocMetrics`: физические строки (LOC), чистый код (SLOC), комментарии, пустые строки.
  - `PackageMetrics`: входящие зависимости (Afferent Coupling $C_a$), исходящие зависимости (Efferent Coupling $C_e$), нестабильность ($I = \frac{C_e}{C_a + C_e}$).
- **Формула архитектурного давления $S_{\text{arch}}$**:
  $$S_{\text{arch}} = 0.1 \cdot \text{SLOC} + 2.0 \cdot N_{\text{functions}} + 3.0 \cdot \text{Cyclomatic} + 1.5 \cdot \text{Deps} + 4.0 \cdot \text{Depth} + 20.0 \cdot D$$
  При превышении порога генерируется предупреждение `ARCH-030` о высоком архитектурном давлении на модуль. Лимит физического размера контролируется правилом `ARCH-031`, а количество функций — правилом `ARCH-032`.

### 6. [`layer.rs`](./src/layer.rs)
- **Ответственность**: Моделирование гексагональных слоев и слоев Feature-Sliced Design (FSD).
- **Как работает**:
  - `HexagonalLayer`: перечисление `Domain`, `Ports`, `Application`, `Infrastructure`, `TauriBootstrap`.
  - Метод `can_depend_on(from, to)` проверяет допустимость зависимости. Например, `Domain` не может зависеть ни от чего; `Application` может зависеть от `Domain` и `Ports`; `Infrastructure` может зависеть от `Ports` и `Domain`.
  - `FsdLayer`: проверка иерархии `app` $\to$ `pages` $\to$ `widgets` $\to$ `features` $\to$ `entities` $\to$ `shared` (запрет восходящих и кросс-слайсовых импортов).

### 7. [`tree.rs`](./src/tree.rs)
- **Ответственность**: Моделирование иерархического дерева компонентов.
- **Ключевые типы**:
  - `ComponentNode`: узел дерева (имя, путь, тип, список дочерних узлов `children`, метрики `AstComplexity`, `SlocMetrics`, список нарушений `violations`).
  - Вычисление агрегированного радиуса взрыва (`Blast Radius`) при изменении узла.

### 8. [`preset.rs`](./src/preset.rs)
- **Ответственность**: Пресеты конфигурации правил.
- **Варианты**:
  - `Strict`: все правила в режиме `Deny` (для релизных веток и финансовых модулей).
  - `Recommended`: баланс между строгостью архитектуры и скоростью разработки.
  - `Relaxed`: предупреждения без блокировки сборки (для прототипирования).

### 9. [`cluster.rs`](./src/cluster.rs)
- **Ответственность**: Модель семантической группы архитектурных нарушений.
- **Поля**: `id`, `label` (смысловое название), `violations` (список связанных нарушений), `centroid` (центроид кластера в векторном пространстве), `density` (плотность кластера).

### 10. [`traits.rs`](./src/traits.rs)
- **Ответственность**: Базовые доменные интерфейсы для парсинга и валидации без привязки к инфраструктуре.
