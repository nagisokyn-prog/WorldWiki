Окей. Давай разберу системно. Сейчас Cerberus — это **«линтер с хорошими правилами»**. Чтобы он стал **«Цербером в буквальном смысле»** — трёхголовым псом, который жрёт всё, что движется — нужно сменить **философию** с «catch violations» на **«express distrust»**.

Разница:
- **Сейчас**: «этот код нарушает правило ARCH-001» → deny.
- **Должно быть**: «этот код **может** нарушить инвариант X при условии Y» → deny.

То есть ты переходишь от **детекции нарушений** к **выражению недоверия**. Это фундаментальный сдвиг.

## Часть 1: Философский сдвиг

Три уровня «злости»:

**Уровень 1: Detection (сейчас).** Ловит известные паттерны нарушений.
- `domain` импортирует `reqwest` → deny.
- `path` из IPC идёт в `Command::new` → deny.

**Уровень 2: Capability (частично есть).** Ловит **возможности**, а не паттерны.
- Этот крейт **может** открыть сокет (через 3 уровня транзитивных зависимостей) → warn.
- Эта функция **может** паниковать на 40% путей исполнения → warn.

**Уровень 3: Distrust (нужно добавить).** Выражает **презумпцию виновности**.
- Любой код, сгенерированный LLM, **обязан** быть покрыт property-based тестом на инварианты → deny без теста.
- Любое изменение в `Cargo.toml` **обязано** иметь capability diff review → deny без подписи.
- Любая функция с I/O **обязана** быть в `infrastructure` или иметь `#[explicit_io]` маркер → deny по умолчанию.

Сейчас у тебя первые два уровня. Третий — твой **реальный дифференциатор**.

## Часть 2: Новые головы Цербера

### Голова 4: PERFORMANCE & SCALABILITY

```
PERF-001: I/O в цикле
  Если функция с capability I/O вызывается внутри for/while/iterator
  → warn (N+1 detection)
  → deny если функция помечена #[hot_path]

PERF-002: Unbounded channel
  tokio::sync::mpsc::channel без ёмкости
  → warn в hot path
  → deny в request handler

PERF-003: CPU-bound в tokio::spawn
  Тело async fn содержит цикл > N итераций без spawn_blocking
  → warn

PERF-004: Синхронный Mutex в async
  std::sync::Mutex в async fn (даже без .await)
  → warn
  → deny если функция вызывается из runtime

PERF-005: Аллокация в hot loop
  Vec::new(), String::new(), format!, .clone() внутри for
  → warn если цикл > 1000 итераций (эвристика)

PERF-006: Blocking в Drop
  impl Drop с fs::write, Command, sleep
  → deny (это UB-риск)

PERF-007: Рекурсия без tail-call
  Рекурсивная функция без явного ограничения глубины
  → warn для production кода

PERF-008: Квадратичная сложность
  Вложенные циклы без ранних выходов и без break
  → warn если оба > N
```

### Голова 5: CONCURRENCY & CORRECTNESS

```
CONC-001: Arc cycle
  Структура содержит Arc<Self> или Arc<Mutex<Vec<Arc<Self>>>>
  → warn (утечка памяти)

CONC-002: spawn без JoinHandle
  tokio::spawn(...) без сохранения handle или CancellationToken
  → deny в production

CONC-003: select! без biased
  tokio::select! без biased и без random fairness
  → warn (недетерминизм под нагрузкой)

CONC-004: RwLock вместо Mutex
  Mutex используется только для чтения в >80% случаев
  → warn (деградация)

CONC-005: Отсутствие CancellationToken
  Long-running task без отмены
  → deny в request handler

CONC-006: Двойной lock
  Один Mutex лочится дважды в одной функции (deadlock)
  → deny (100% deadlock)

CONC-007: Unsafe Send/Sync
  impl Send/Sync для типа с raw pointers
  → deny без #[safety_comment]

CONC-008: Static mut
  static mut ANY_TYPE
  → deny (UB)

CONC-009: Interrupt-safe
  Mutex, held через .await
  → deny (уже есть как ASYNC-002)
```

## Часть 3: Cross-cutting — то, что делает правила «умнее»

**1. Capability Budget (вместо бинарного deny).**
```toml
[capabilities.domain]
max_network_calls = 0
max_fs_writes = 0
max_process_spawns = 0
max_env_reads = 0
max_unsafe_blocks = 0

[capabilities.application]
max_network_calls = 5   # явно разрешено 5, с обоснованием
max_fs_writes = 0
```

Вместо «domain не может делать X» → «domain может делать X **не более N раз**, и каждый вызов задокументирован».

**2. Cross-language taint.**
Сейчас taint только внутри Rust или внутри Vue. Нужен **сквозной**:
- Аргумент Tauri IPC (Rust side) → taint → параметр в Vue компоненте.
- Если этот параметр попадает в `v-html` без sanitize → deny.

Это **реально уникально**. Никто такого не делает.

**3. Provenance tracking.**
```rust
// В коде есть маркер
#[generated_by(llm, model = "claude-opus", commit = "abc123")]
```
Правила могут **ужесточаться** для LLM-генерированного кода:
- TEST-001..010 применяются только к LLM-коду.
- Требуется property-based test.
- Требуется human review для unsafe.

Это можно **автоматически** определять через `git log --grep="Co-authored-by:"`.

**4. Invariants DSL (расширение architecture-as-config).**
```toml
[[invariant]]
id = "INV-MONEY-001"
description = "Все денежные операции идемпотентны"
assert = "all fn in domain::money have #[idempotent]"
severity = "deny"

[[invariant]]
id = "INV-EVENT-001"
description = "Все события имеют version"
assert = "all struct impl Event have field version"
severity = "deny"
```

Это **policy layer**, который позволяет выражать **бизнес-инварианты**, а не только технические.

**5. Temporal rules.**
Правила, которые проверяют **diff между коммитами**, а не только текущий код:
- «Этот PR добавил 3 новых capability без изменения ADR» → warn.
- «Этот PR удалил 5 тестов и не добавил новых» → deny.
- «Этот PR изменил публичный API без bump версии» → deny.

**6. Rules as Code (расширение).**
Позволить писать правила на **Rust** (как `cargo-deny`), **TOML** (декларативно) и **WASM** (для переносимости). Тогда сообщество начнёт контрибьютить.

## Часть 4: Как сделать существующие правила злее

**1. Уровень строгости по умолчанию → `deny`.**
Сейчас много `warn`. Сделай так, чтобы в пресете `hardened-sandbox` **всё** было `deny`, кроме `OBS-*` и `PERF-*` (которые `warn`).

**2. Правила на **дизайн**, не только на нарушения.**
- Отсутствие ADR для нового архитектурного решения → deny.
- Отсутствие `#[doc]` для публичного API → warn.
- Отсутствие `#[safety_comment]` для unsafe → deny (уже есть).

**3. Правила на **тренды**, не только на точки.**
- «S_arch растёт на > 5% за PR» → deny.
- «Test coverage падает на > 2% за PR» → deny.
- «Количество `.clone()` растёт на > 10% за PR» → warn.

**4. Правила на **аномалии**, не только на паттерны.**
- «Эта функция имеет 200 строк и 0 вызовов из других модулей» → warn (мёртвый код).
- «Этот файл был изменён 47 раз за месяц» → warn (hot spot).
- «Этот крейт используется только одним модулем» → warn (возможно, не нужен).

**5. Правила на **контракты**, не только на синтаксис.**
- «Публичная функция возвращает `impl Trait`, но трейт не sealed» → warn.
- «Публичный enum не помечен `#[non_exhaustive]`» → warn.
- «Публичный struct имеет публичные поля» → warn.
