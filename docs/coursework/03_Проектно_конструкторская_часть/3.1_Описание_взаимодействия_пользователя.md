### Детальная спецификация базовых сценариев

#### UC-01: Создание нового литературного проекта и настройка структуры произведения
- **Главный актор:** Автор.
- **Предусловия:** Запущено главное окно системы, база данных инициализирована.
- **Основной поток событий:**
  1. Автор нажимает экранную кнопку «Новый проект».
  2. В модальном диалоге автор указывает наименование произведения, жанр, автора и целевой объем.
  3. Система создает транзакционную запись проекта в локальной базе данных.
  4. Автоматически формируется начальная иерархическая структура: том по умолчанию, первая сюжетная арка и первая глава.
  5. В навигационном дереве отображается созданная структура, рабочая область переключается в режим редактирования первой главы.
- **Постусловия:** Проект создан и готов к заполнению текстом.

#### UC-02: Постраничное форматирование рукописи в Word-режиме (ГОСТ 7.32)
- **Главный актор:** Автор.
- **Предусловия:** Открыта глава произведения, активирован постраничный режим.
- **Основной поток событий:**
  1. Редактор инициализирует постраничную разметку с размерами листа A4/A5, полями и градуированной линейкой.
  2. Автор выполняет ввод текста, оформляет заголовки, списки, цитаты и сноски.
  3. Линейка отображает текущий абзацный отступ (1.25 см по стандарту).
  4. При заполнении страницы система автоматически выполняет перенос строк на следующую страницу.
  5. Фоновый механизм с интервалом дебаунса сохраняет снимки документа в локальной базе данных.
- **Постусловия:** Текст сохранен с сохранением физической структуры страниц.

#### UC-04: Инлайн-линковка сущностей через синтаксис `((Имя))` с автодополнением
- **Главный актор:** Автор.
- **Предусловия:** Текстовый процессор находится в режиме редактирования, в базе данных есть записи о сущностях.
- **Основной поток событий:**
  1. Автор вводит в редакторе открывающую комбинацию символов `((`.
  2. Система перехватывает ввод и открывает контекстное меню автодополнения с фильтрацией по именам сущностей.
  3. Автор выбирает требуемую сущность клавишами навигации или щелчком мыши.
  4. Редактор вставляет неразрывный интерактивный блок `((Наименование))`.
  5. В базе данных автоматически формируется графовая связь появления сущности в текущей главе (`appears_in`).
- **Постусловия:** Сущность связана с текстом главы, обновлен граф упоминаний.

#### UC-07: Установление направленной темпоральной связи между сущностями
- **Главный актор:** Автор.
- **Предусловия:** В базе данных зарегистрированы исходная и целевая сущности.
- **Основной поток событий:**
  1. Автор открывает вкладку связей в карточке сущности и выбирает опцию «Добавить связь».
  2. Указывается целевая сущность, тип отношения (родство, союз, подчинение, вражда) и признак двунаправленности.
  3. Выставляется числовая шкала доверия/силы от -100 до +100.
  4. Задаются границы актуальности отношения (начальный том/глава и конечный том/глава).
  5. Вводится текстовое обоснование изменения отношений.
  6. Данные сохраняются в графовой таблице связей базы данных.
- **Постусловия:** Графовое ребро зафиксировано и отображается на диаграмме отношений.

#### UC-10: Добавление события хронологии и расчет абсолютной минуты ($M_{\text{abs}}$)
- **Главный актор:** Автор.
- **Предусловия:** В проекте настроена хотя бы одна календарная система.
- **Основной поток событий:**
  1. Автор открывает временную шкалу и нажимает «Добавить событие».
  2. Задаются наименование, описание и категория события.
  3. В виджете ввода даты указываются эпоха, год, месяц, день, часы и минуты.
  4. Алгоритмический модуль рассчитывает координату абсолютной минуты $M_{\text{abs}}$ от базовой точки отсчета.
  5. Событие связывается с главой текста и участвующими персонажами.
  6. Запись сохраняется в базе данных с индексом по временной координате.
- **Постусловия:** Событие упорядочено на шкале времени и доступно в хронологии.

#### UC-18: Экспорт рукописи в типографический формат DOCX (ГОСТ 7.32)
- **Главный актор:** Автор.
- **Предусловия:** Проект содержит структурированные главы с текстом, открыта панель экспорта.
- **Основной поток событий:**
  1. Автор выбирает формат экспорта (DOCX) и профиль оформления («ГОСТ 7.32»).
  2. Подсистема экспорта формирует нормализованную AST-модель документа.
  3. Модуль компиляции бэкенда генерирует файл OpenXML с нормативными стилями: гарнитура Times New Roman 14 пт, межстрочный интервал 1.5, абзацный отступ 1.25 см, выравнивание по ширине, сквозная нумерация страниц.
  4. Готовый документ сохраняется в каталоге загрузок пользователя.
  5. Пользователю выводится уведомление с путем к созданному файлу.
- **Постусловия:** Сформирован файл DOCX, готовый к печати или отправке в издательство.
