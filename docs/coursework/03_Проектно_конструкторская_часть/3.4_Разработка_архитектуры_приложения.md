## 3.4. Разработка архитектуры приложения

### 3.4.1. Общая архитектурная концепция
Архитектура программного комплекса «WorldWiki» строится на принципах слабой связанности (Loose Coupling), высокой связности модулей (High Cohesion) и полной изоляции доменной логики от платформо-зависимых интерфейсов.

Общая структура взаимодействия компонентов представлена тремя основными уровнями:
1. **Уровень представления (Frontend):** клиентское одностраничное приложение (`apps/spa`) на базе Vue 3, TypeScript и Vite, опирающееся на общие пакеты монорепозитория (`packages/*`) и функционирующее внутри WebView2.
2. **Уровень межпроцессного взаимодействия (Tauri IPC Bridge):** легковесный слой сериализации/десериализации команд и передачи бинарных буферов между JavaScript и Rust.
3. **Уровень прикладного ядра (Backend Core):** нативное ядро на языке Rust, реализующее бизнес-логику, математические модели и работу с базой данных SurrealDB поверх переиспользуемого инфраструктурного каркаса `tauri-surreal-kit`.

---

### 3.4.2. Гексагональная архитектура бэкенда (`Ports & Adapters`) и `tauri-surreal-kit`
Для исключения жесткой привязки к конкретным библиотекам и фреймворкам нативный бэкенд организован в виде workspace из изолированных Cargo-крейтов в соответствии с гексагональным архитектурным паттерном, а общие платформенные примитивы вынесены в каркас **`tauri-surreal-kit`**:

- **`tauri-surreal-kit`** инкапсулирует нормализацию идентификаторов и базовый репозиторий (`surreal_domain_core`), процедурные макросы генерации IPC-мостов (`surreal_domain_macros`), а также системное управление окнами, темами и бенчмаркингом производительности (`SurrealDB` + `Tauri`).
- **`src-tauri/crates/*`** реализует предметную область, порты, сценарии использования (`application`) и изолированные `#![no_std]` вычислительные ядра.

Полная структурно-архитектурная схема программного комплекса (гексагональный бэкенд, Tauri IPC, FSD/MVVM-фронтенд и `#![no_std]`-ядра) вынесена в графическую часть курсового проекта — **Лист 2 (формат А3)** ([architecture_and_math_a3.svg](../diagrams/architecture_and_math_a3.svg)).

**Ключевые архитектурные инварианты бэкенда:**
1. **Изоляция домена:** модули `domain` и `application` не содержат зависимостей от `tauri`, `surrealdb` или сетевых библиотек, что обеспечивает возможность независимого модульного тестирования бизнес-логики без поднятия GUI.
2. **Инверсия зависимостей:** слой инфраструктуры реализует интерфейсы, объявленные в портах (`ports`), а не диктует свои правила прикладным сценариям.
3. **Изоляция IPC и переиспользуемость каркаса:** адаптер Tauri является единственной точкой входа команд от пользовательского интерфейса, используя макросы и примитивы `tauri-surreal-kit` для безопасного маппинга запросов в вызовы `application`.

### 3.4.3. Модель семантического документа (AST) как единый источник правды
Для обеспечения взаимной согласованности между визуальным редактором, базой знаний и полнотекстовым поиском разработана абстрактная синтаксическая модель `SemanticDocument`.

Текст рукописи нормализуется в виде типизированного дерева узлов:
- `DocumentNode` — корневой контейнер с метаданными главы;
- `ParagraphNode` — абзац текста со статистическими характеристиками;
- `EntityMentionNode` — специальный узел упоминания объекта лора с привязкой к ID сущности;
- `FootnoteNode` — подстрочная сноска;
- `HeadingNode`, `ImageNode`, `TableNode` — структурные блоки разметки.

Адаптер `ASTAdapter` обеспечивает двунаправленную бесшовную трансляцию между:
- внутренним представлением редактора Tiptap (JSON Schema);
- блочной моделью базы данных `text_blocks`.

### 3.4.4. Архитектура фронтенда: монорепозиторий (`packages/`), FSD и MVVM
Клиентская часть организована в виде `pnpm`-монорепозитория, разделяющего основное приложение (`apps/spa`) и переиспользуемые пакеты (`packages/`):
- **`@worldwiki/components`** — библиотека базовых UI-компонентов и дизайн-токенов;
- **`@worldwiki/calendar-wasm`**, **`@worldwiki/ast-diff-wasm`**, **`@worldwiki/manuscript-wasm`** — WASM-пакеты поверх `#![no_std]` Rust-ядер для клиентских вычислений;
- **`packages/resources`** — общие ресурсы и ассеты приложения.

Внутри `apps/spa` код структурирован по методологии **Feature-Sliced Design (FSD)** (`app -> features -> composables -> stores / services -> types / utils`) с однонаправленными импортами сверху вниз, а каждый UI-модуль строится по 4-компонентной схеме паттерна **MVVM** (визуальная схема приведена на **Листе 2 формата А3** — [architecture_and_math_a3.svg](../diagrams/architecture_and_math_a3.svg)):

1. **Декларативный шаблон (`Component.vue`):** содержит только разметку (`View`) и компактный связующий клей без прямых вызовов Tauri IPC.
2. **Логический хук (`useComponent.ts`):** выступает в роли `ViewModel`, инкапсулируя реактивное состояние (`ref`, `computed`), бизнес-логику и взаимодействие с хранилищем Pinia.
3. **Модель типов (`Component.model.ts`):** содержит строгие TypeScript-интерфейсы `Props`, `Emits` и DTO.
4. **Модульный тест (`Component.spec.ts`):** набор автоматических unit-тестов логики хука.
