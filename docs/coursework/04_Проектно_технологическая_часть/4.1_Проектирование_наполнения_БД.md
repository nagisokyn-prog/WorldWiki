# 4. ПРОЕКТНО-ТЕХНОЛОГИЧЕСКАЯ ЧАСТЬ

## 4.1. Проектирование наполнения базы данных и структуры SurrealQL

### 4.1.1. Декларативная схема таблиц и триггеров
Информационная база данных разворачивается средствами декларативного языка SurrealQL (полный DDL-скрипт физической схемы приведён в [Приложении А](../Приложение_А_Физическая_схема_БД.md)). При проектировании схемы реализованы следующие ключевые конструкции:

```surrealql
-- Определение схемы проектов и каскадного удаления
DEFINE TABLE OVERWRITE projects SCHEMAFULL;
DEFINE FIELD OVERWRITE name       ON projects TYPE string;
DEFINE FIELD OVERWRITE genres     ON projects TYPE array<string> DEFAULT [];
DEFINE FIELD OVERWRITE created_at ON projects TYPE option<datetime | null> DEFAULT time::now();

DEFINE EVENT OVERWRITE cascade_project_delete ON TABLE projects WHEN $event = "DELETE" THEN {
    LET $p_rec = fn::normalize_project_id($before.id);
    LET $arcs = (SELECT VALUE id FROM story_arcs WHERE project_id = $p_rec);
    LET $schemas = (SELECT VALUE id FROM entity_schemas WHERE project_id = $p_rec);
    DELETE todos WHERE owner_id = $p_rec OR owner_id IN $arcs;
    DELETE volumes WHERE project_id = $p_rec;
    DELETE entities WHERE schema_id IN $schemas;
    DELETE timeline_events WHERE project_id = $p_rec;
};

-- Определение иерархии глав и ребер отношений
DEFINE TABLE OVERWRITE chapters SCHEMAFULL CHANGEFEED 30d;
DEFINE FIELD OVERWRITE volume_id  ON chapters TYPE record<volumes>;
DEFINE FIELD OVERWRITE title      ON chapters TYPE string;
DEFINE FIELD OVERWRITE sort_order ON chapters TYPE int DEFAULT 0;
DEFINE FIELD OVERWRITE word_count ON chapters TYPE int DEFAULT 0;

-- Графовая таблица отношений между сущностями
DEFINE TABLE OVERWRITE entity_rel TYPE RELATION IN entities OUT entities SCHEMAFULL;
DEFINE FIELD OVERWRITE rel_type   ON entity_rel TYPE string;
DEFINE FIELD OVERWRITE strength   ON entity_rel TYPE option<int | null>;
DEFINE FIELD OVERWRITE start_at   ON entity_rel TYPE option<record<chapters | volumes> | null>;
DEFINE FIELD OVERWRITE end_at     ON entity_rel TYPE option<record<chapters | volumes> | null>;
```

---

### 4.1.2. Проектирование индексов быстродействия
Для оптимизации времени выполнения аналитических и поисковых запросов в схеме базы данных настроены специализированные индексы:
1. **Индекс временной шкалы:** B-Tree индекс по числовому полю `m_abs` таблицы `timeline_events` обеспечивает логарифмическую сложность выборки диапазона событий $O(\log N + K)$.
2. **Полнотекстовые индексы (`FULLTEXT`):** индексы по полям наименования и описания сущностей (`entities`) и текста глав (`chapters`) с учетом русской и английской лемматизации (`ru_en_analyzer`).

### 4.1.3. Тестовое наполнение и валидация миграций
Для верификации структуры базы данных разработан генератор синтетических данных, создающий тестовый литературный проект («Сага о Семи Королевствах»), включающий:
- 3 тома, 9 сюжетных арок и 27 глав;
- 60 сущностей базы знаний (персонажи, фракции, замки, реликвии);
- свыше 150 графовых ребер взаимоотношений (`entity_rel`) с различными весами силы и временными рамками;
- 2 авторские календарные системы («Имперское летоисчисление» и «Лунный календарь кочевников») с 40 синхронизированными событиями хронологии.

Тестирование подтвердило корректность работы каскадных триггеров и сохранение целостности базы данных при стрессовых модификациях схемы.
