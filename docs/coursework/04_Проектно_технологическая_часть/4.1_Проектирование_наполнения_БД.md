# 4. ПРОЕКТНО-ТЕХНОЛОГИЧЕСКАЯ ЧАСТЬ

## 4.1. Проектирование наполнения базы данных и структуры SurrealQL

### 4.1.1. Инициализация, миграция схемы и индексы быстродействия
Информационная база данных разворачивается декларативными скриптами `SurrealQL` (полный DDL-код таблиц, индексов, событий и функций приведён в [Приложении Д](../Приложение_Д_Физическая_схема_БД.md)). Для идемпотентного обновления схемы при старте приложения все определения содержат модификатор `OVERWRITE`, а версия применённого DDL контролируется по хэшу `system_meta.ddl_hash`. Все прикладные запросы параметризуются на 100% через `.bind()` без строковой конкатенации.

Для ускорения аналитических и поисковых выборок настроены специализированные индексы:
1. **Временная шкала (`B-Tree`):** индекс по скалярному полю `m_abs` таблицы `timeline_events` обеспечивает логарифмическую сложность диапазонных выборок $O(\log N + K)$.
2. **Полнотекстовый поиск (`FULLTEXT`):** индексы по полям сущностей (`entities`) и глав (`chapters`) с лемматизацией русского и английского языков (`ru_en_analyzer`).
3. **Внешние связи:** явные `B-Tree` индексы на всех полях `project_id`, `in` и `out` таблиц-рёбер.

### 4.1.2. Апробация структуры БД и проверка целостности
Работоспособность физической схемы, хранимых функций (`fn::*`) и каскадных триггеров `DEFINE EVENT` подтверждена в ходе интеграционных тестов на встроенном движке `SurrealKV`/`kv-mem` (проверка ограничений `SCHEMAFULL`, каскадного удаления проектов, томов, глав, сущностей и перепривязки календарей) и в условиях реальной эксплуатации при работе с авторской рукописью, базой знаний лора и многокалендарной хронологией.
