## 4.2. Реализация математических моделей и алгоритмов

Обобщённая структурно-алгоритмическая схема всех `#![no_std]` вычислительных ядер и их интеграция с гексагональной архитектурой приложения приведена в графической части курсового проекта — **Лист 2 (формат А3)** ([architecture_and_math_a3.svg](../diagrams/architecture_and_math_a3.svg)).

### 4.2.1. Математическая модель универсального времени и календарного ядра (`worldwiki-calendar-core`)

Для синхронизации событий разнородных вымышленных, исторических и мультипланетных календарных систем в изолированном `#![no_std]`-крейте `worldwiki-calendar-core` реализована целочисленная математическая модель без использования чисел с плавающей точкой в критических путях вычислений.

#### 1. Вселенский физический скаляр $t_{\text{abs}}$ и проекция на циферблаты
Базовой координатой времени выступает монотонная непрерывная целочисленная величина $t_{\text{abs}} \in \mathbb{Z}$ (`i64`) в физических тиках (нанометрах шкалы / микросекундах / секундах), связанная с локальным моментом планеты $(\text{world\_day}, \text{day\_tick})$ через **евклидово деление** (`div_euclid`, `rem_euclid`), гарантирующее корректность вычислений для эпох до сотворения мира ($t_{\text{abs}} < 0$):

$$\text{world\_day} = \left\lfloor \frac{t_{\text{abs}}}{T_{\text{day}}} \right\rfloor_{\text{euclid}}, \qquad \text{day\_tick} = t_{\text{abs}} \bmod_{\text{euclid}} T_{\text{day}}, \qquad 0 \le \text{day\_tick} < T_{\text{day}}$$

где $T_{\text{day}}$ — физическая длительность суток планеты в тиках. Смещение начала календарных суток относительно астрономической полночи (рассвет, закат) задаётся циклическим сдвигом `day_start_offset` $\in [0, T_{\text{day}})$.

Произвольное культурное деление суток (часы/минуты/секунды, десятичные доли, стражи ночи) описывается иерархией `DialHierarchy` с полной ёмкостью $C = \prod_i s_i$. Прямое и обратное преобразование между показаниями циферблата $U_{\text{day}} \in [0, C)$ и физическим тиком суток выполняется каскадным квантованием (`ceil`/`floor`) без потери квантов на границах делений:

$$\text{day\_tick} = \left\lceil \frac{U_{\text{day}} \cdot T_{\text{day}}}{C} \right\rceil = \left\lfloor \frac{U_{\text{day}} \cdot T_{\text{day}} + C - 1}{C} \right\rfloor, \qquad U_{\text{day}} = \left\lfloor \frac{\text{day\_tick} \cdot C}{T_{\text{day}}} \right\rfloor$$

При $T_{\text{day}} \bmod C = 0$ обеспечивается строгая биективность квантования. Для прикладного уровня в системе также используется производная координата абсолютной минуты $M_{\text{abs}} \in \mathbb{Z}$.

#### 2. Обобщённый гармонический движок високосных циклов ($O(k)$)
Вместо линейного перебора лет ($O(Y)$) накопленное количество високосных дней до года $Y$ включительно вычисляется аналитически по **обобщённой гармонической формуле**:

$$F(Y) = \sum_{i=1}^{k} w_i \left\lfloor \frac{a_i Y + b_i}{c_i} \right\rfloor_{\text{floor}}$$

где $w_i \in \mathbb{Z}$ — вес гармоники (обычно $\pm 1$), $a_i$ — множитель, $b_i$ — фазовый сдвиг, $c_i > 0$ — период гармоники, $k$ — число гармоник (например, для григорианского календаря $k = 3$: $+ \lfloor Y/4 \rfloor - \lfloor Y/100 \rfloor + \lfloor Y/400 \rfloor$). Признак високосности года $Y$ определяется как конечная разность $\Delta F(Y) = F(Y) - F(Y - 1) \in \{0, 1\}$, а суммарное число суток до начала года $Y$ вычисляется в 128-битной арифметике (`i128`) за $O(k)$ операций с защитой от переполнений.

#### 3. Обратный поиск года за $O(1)$ и разложение в цепные дроби
- **Обратное преобразование `year_from_days_o1`**: по порядковому дню $\text{cal\_day}$ аналитически вычисляется оценка года $Y_0$ через взвешенную среднюю длину года:
  $$\overline{D}_{\text{year}} = D_{\text{base}} + d \cdot \sum_{i=1}^{k} \frac{w_i a_i}{c_i}$$
  с гарантированной доводкой за $0..2$ шага коррекции без циклического перебора эпох.
- **Цепные дроби и рациональный дрейф:** произвольная дробная часть тропического года $p/q$ раскладывается в непрерывные цепные дроби до глубины 10 и декомпозируется в систему знаковых единичных гармоник $\pm 1$ (пример сходимости для земного тропического года приведён в таблице 4.1). Вековой дрейф календаря вычисляется строго в рациональной арифметике `i128` (в промилле суток за столетие) без погрешностей `f64`.

#### 4. Целочисленная планетарная астрономия и алгебра интервалов Аллена
В ядре `worldwiki-calendar-core` без использования `libm` и `f64` реализован расчёт солнечного полудня, зенитного расстояния $[0..180\,000]$ мград, инсоляции, фаз произвольного числа лун (в базисных пунктах с точностью $< 1$ суток за $500\,000$ лет), исторических реформ и цепочек синхронизации календарей (полный конвейер ядра 3.1 показан на **Листе 2 А3**). Для формального аудита временной непротиворечивости лора реализованы все 13 отношений интервальной алгебры Аллена (таблица 4.2).

Таблица 4.2 — 13 взаимно-исключающих отношений алгебры Аллена над полуоткрытыми интервалами $[a_s, a_e)$ и $[b_s, b_e)$

| Группа отношений Аллена | Формальное условие над $[a_s, a_e)$ и $[b_s, b_e)$ | Семантика при аудите интервалов |
|---|---|---|
| `Before` / `After` | $a_e < b_s$ / $a_s > b_e$ | Интервалы строго не пересекаются (разделены во времени, коллизии нет) |
| `Meets` / `MetBy` | $a_e = b_s$ / $a_s = b_e$ | Стык полуоткрытых интервалов в граничной точке (пересечение пустое) |
| `Overlaps` / `OverlappedBy` | $a_s < b_s < a_e < b_e$ / $b_s < a_s < b_e < a_e$ | Частичное перекрытие интервалов (сигнал возможной билокации персонажа) |
| `Starts` / `StartedBy` | $a_s = b_s \land a_e < b_e$ / $a_s = b_s \land a_e > b_e$ | Совпадающее начало при разной длительности (одновременное присутствие на отрезке) |
| `During` / `Contains` | $a_s > b_s \land a_e < b_e$ / $a_s < b_s \land a_e > b_e$ | Строгое вложение одного интервала в другой (событие внутри времени жизни) |
| `Finishes` / `FinishedBy` | $a_s > b_s \land a_e = b_e$ / $a_s < b_s \land a_e = b_e$ | Совпадающее окончание при разном начале (пересечение на общем хвосте) |
| `Equals` | $a_s = b_s \land a_e = b_e$ | Полное совпадение двух временных отрезков |

### 4.2.2. Алгоритм структурного сравнения и патчинга AST (Myers Diff, `worldwiki-document-core`)

Для сравнения ревизий глав (`chapter_revisions`) на уровне семантического дерева `SemanticDocument` в изолированном `#![no_std]`-крейте `worldwiki-document-core` реализован **алгоритм Майерса** (временная сложность $O((N + M) D)$, где $N, M$ — длины последовательностей блоков, $D$ — минимальное число операций редактирования `EditOp`). ### 4.2.3. Конечный автомат извлечения сущностей и разрешения ссылок (`worldwiki-manuscript-core`)

Распознавание упоминаний объектов базы знаний формата `((Сущность))` в тексте рукописи выполняется детерминированным конечным автоматом (`extract_entity_mentions`, сложность $O(N)$ за один линейный проход без регулярных выражений и бэктрекинга), а разрешение перекрёстных ссылок (`resolve_cross_references`) — по индексной хэш-таблице за $O(1)$ в среднем на ссылку. Диаграмма переходов состояний автомата приведена в блоке 3.3 **Листа 2 А3**.

### 4.2.4. Обратная совместимость динамических схем

При изменении структуры карточек сущностей (`UPSERT` новой декларации `fields_schema` в `entity_schemas`) применяется **ленивая обратная совместимость без миграционной перезаписи БД** (версионность в текущей реализации поддерживается только для глав в `chapter_revisions`): ранее сохранённые значения в `entities.attributes` (`object FLEXIBLE`) сохраняются, а подстановка значений по умолчанию для новых полей выполняется лениво при открытии формы (блок 3.3 **Листа 2 А3**).
