## 4.3. Тестирование, формальная верификация и приёмочные испытания

### 4.3.1. Методика верификации и испытаний
Для контроля корректности реализации организован четырёхуровневый контур проверки:
1. **Модульные и интеграционные тесты бэкенда (`cargo test`, `llvm-cov`):** проверка доменных правил, use-case сценариев и интеграции с `SurrealDB` (каскады, `SCHEMAFULL`, `UNIQUE`).
2. **Формальная верификация (`Kani Rust Verifier`):** доказательство отсутствия паник, переполнений, выхода за границы массивов и нарушений биективности в критических модулях (`#[kani::proof]`).
3. **Тесты фронтенда (`Vitest`, `v8`):** проверка `use*.ts`-хуков, Pinia-хранилищ, откатов при ошибках и граничных случаев.
4. **Статический аудит:** проверка типов (`tsc --noEmit`, `cargo check --all-targets`) и архитектурного файрвола `Cerberus`.

### 4.3.3. Результаты контрольных испытаний
Испытания собранного приложения на ОС Microsoft Windows 10/11 подтвердили выполнение эксплуатационных требований ТЗ: размер исполняемого файла со встроенной СУБД `SurrealKV` составляет **54 МБ**, потребление ОЗУ в активном многооконном режиме — **350–400 МБ**, адаптивные профили рендеринга (`High` / `Medium` / `Low`) обеспечивают плавную работу интерфейса без внешней серверной инфраструктуры.
