# 🔄 Ревизия Существующих Модулей (С Учетом Хардкода Системных Полей)

> **Область действия**: Все аналитические, графовые и редакторские модули WorldWiki.
> **Статус**: Архитектурная ревизия ядра.

---

## 📌 1. Зачем Потребовалась Ревизия

Ранее система строилась на предположении о полностью «динамических» полях сущностей, что приводило к хрупкости аналитики:
* Если автор переименовывал поле «Статус» в «Состояние» или менял значение с «Мёртв» на «Погиб в бою», **все SQL-функции SurrealDB и Rust-аудиты ломались**, так как искали жесткий ключ `is_deceased`.
* Расчет возраста в сценах был невозможен, так как дата рождения могла лежать по случайному JSON-пути `attributes.some_custom_date`.
* Графы отношений не могли гарантировать наличие силы связи в диапазоне $-100 \dots +100$.

**Переход на жесткие системные поля (Hardcoded Contract)** гарантирует 100% стабильность аналитических алгоритмов. Ниже описано, как именно обновляется работа каждого существующего модуля.

## 📊 2. Матрица Пересечений (Cross-Reference Matrix & Heatmap)

### 🔴 Было:
* Читала неструктурированный флаг `attributes.is_deceased`.
* Выводила всех персонажей подряд по алфавиту.
* Предупреждение о пропуске глав (Буровский эффект) срабатывало одинаково на всех подряд (даже на эпизодического трактирщика).

### 🟢 Стало (Ревизия):
1. **Жесткая привязка к `статус_категория`**:
   * Если `статус_категория == "Мёртв"` $\to$ персонаж автоматически получает метку 💀 и серую штриховку всех ячеек после главы гибели.
2. **Интеллектуальная сортировка по `роль_в_истории`**:
   * Строки матрицы автоматически группируются:
     1. ⭐ **Главные герои** (верхний блок);
     2. ⚔️ **Антагонисты**;
     3. 👥 **Второстепенные персонажи**;
     4. 엑 **Эпизодические** (свернуты по умолчанию).
3. **Дифференцированный Буровский аудит**:
   * Для `Главного героя`: алерт при отсутствии **3+ глав** подряд.
   * Для `Второстепенного`: алерт при отсутствии **8+ глав** подряд.
   * Для `Эпизодического`: проверка отключена (не засоряет эфир).

## 🗺️ 3. Навигатор Пути Персонажа (Character Journey)

### 🔴 Было:
* Работал строго с одним `entity_id`.
* Не рассчитывал возраст героя в конкретных сценах.
* Не учитывал перемещения по географической иерархии.

### 🟢 Стало (Ревизия):
1. **Динамический возраст в каждой сцене**:
   * На основе жесткого поля `дата_рождения` ($M_{\text{abs\_birth}}$) и времени сцены ($M_{\text{abs\_scene}}$) карточка сцены выводит точный возраст: *«Сонечка (19 лет, 4 мес.)»*.
2. **Мульти-персонажный режим (Multi-Entity Overlap)**:
   * Выбор нескольких героев $\to$ автоматическое слияние узлов дерева по сценам $\to$ вывод точек пересечения.
3. **Хроника изменений статуса**:
   * Узлы дерева подсвечивают смену `статус_категория` (например, переход из `Жив` в `Пропал без вести` в Главе 8).

## 🛡️ 4. Движок Аудита Непротиворечивости (Consistency Audit Engine)

### 🔴 Было:
* Реализованы только 4 базовых правила (смерть, анахронизм раскрытия, билокация по времени, отсутствие в главах).

### 🟢 Стало (Ревизия):
Благодаря хардкоду 6 сущностей движок расширяется до **8 автоматических инвариантов**:

| ID Правила | Название правила | Используемые системные поля | Действие при нарушении |
|---|---|---|---|
| **`RULE-01`** | **Действие после смерти** | `статус_категория == "Мёртв"`, `дата_смерти` ($M_{\text{abs}}$) | 🔴 **Critical Anomaly**: появление персонажа в сцене позже момента смерти. |
| **`RULE-02`** | **Действие до рождения** | `дата_рождения` ($M_{\text{abs}}$) | 🔴 **Critical Anomaly**: персонаж действует до своего рождения. |
| **`RULE-03`** | **Временная билокация** | Сцены с одинаковым $M_{\text{abs}}$ | 🟡 **Warning**: персонаж одновременно в двух событиях. |
| **`RULE-04`** | **Пространственный телепорт** | Локации сцен, `родительская_локация`, $\Delta M_{\text{abs}}$ | 🟡 **Warning**: мгновенное перемещение между далекими регионами. |
| **`RULE-05`** | **Телепортация артефакта** | `item.история_владения`, участники сцены | 🔴 **Warning**: предмет используется героем, не являющимся текущим владельцем. |
| **`RULE-06`** | **Действие в разрушенной локации** | `location.статус_категория == "Разрушена"` | 🟡 **Warning**: проведение сцены в уничтоженном месте. |
| **`RULE-07`** | **Буровский эффект** | `character.роль_в_истории`, главы | 🔵 **Notice**: долгое отсутствие протагониста в тексте. |
| **`RULE-08`** | **Забытое Чеховское ружье** | `item.статус_категория`, главы ввода | 🔵 **Notice**: предмет не используется более 10 глав. |

## 🕸️ 5. Временной Срез Графа Отношений (Graph Time Slice)

### 🔴 Было:
* Строил статичный граф без строгой фильтрации по времени глав.

### 🟢 Стало (Ревизия):
1. **Точная динамика по `relationshipStates`**:
   * Каждое ребро графа строго привязано к `manuscript_point` (`начальная_глава` и `конечная_глава` с флагом `is_auto_extend`).
2. **Срез на выбранную главу**:
   * Ползунок глав отсекает неактуальные связи и перекрашивает ребра в зависимости от силы связи (зеленый: $+1 \dots +100$, красный: $-1 \dots -100$, серый: $0$).

## 🎨 6. Редактор Схем (Schema Studio / Schema Editor)

### 🔴 Было:
* Пользователь мог случайно удалить поле «Название» или «Статус», сломав карточку и базу данных.

### 🟢 Стало (Ревизия):
1. **Иммутабельные системные поля (`isSystem: true`)**:
   * В UI редактора схем у системных полей **отсутствует кнопка «Удалить» (крестик) и «Скрыть»**.
   * Заблокировано изменение системного идентификатора (`id`) и пути в данных (`path`).
   * Заблокировано удаление канонических значений в выпадающих списках (например, нельзя удалить опцию «Мёртв» из `статус_категория`).
2. **Полная свобода для кастомных полей**:
   * Автор по-прежнему может добавлять любые свои страницы, секции, текстовые поля, числовые ползунки и теги — они сохраняются в `attributes.*` и не конфликтуют с ядром.
