# Архитектурный Roadmap "World-Wiki Ultimate"

Здесь собран анализ амбициозных фич и технический стек, который потребуется для их реализации.

## 1. Структура "Том-Арка-Глава"
**Оценка:** Легко.
**Реализация:** Добавление промежуточных таблиц в SQLite (`volumes`, `arcs`) и реализация древовидного UI (Tree View) в сайдбаре, как в проводнике VS Code.

## 2. Разделение текста по смыслу (Мысли, Диалоги, Описания)
**Оценка:** Хардкор.
**Реализация:** Обычный Markdown-редактор (ToastUI) с этим не справится красиво. Требуется переход на **Блочный редактор (TipTap или ProseMirror)**. 
Вместо сырого текста в БД сохраняется AST-дерево (JSON), где каждый абзац имеет тип: `type: "dialogue"`, `type: "thought"`. При рендере редактора к ним применяются разные стили (и даже иконки на полях), а для LLM это выгружается как структурированный массив.

## 3. VS Code Experience (Сплит-скрин, параллельное редактирование)
**Оценка:** Сложно, но очень круто.
**Реализация:** Потребуется менеджер окон (оконная система внутри SPA) — например, `GoldenLayout` или самописная логика на Vue + Pinia. Состояние всех панелей (где какой файл открыт) хранится глобально. Компоненты-редакторы должны быть реактивными: если в левом сплите ты меняешь имя персонажа, в правом сплите (где открыто досье) оно должно обновиться в реальном времени.

## 4. Консоль с синтаксисом SQLite
**Оценка:** Средне.
**Реализация:** Фронтенд работает как терминал, передает SQL-строку на Rust-бекэнд (Tauri), который выполняет `db.execute(query)` и возвращает сырой JSON с данными, который фронтенд парсит и рисует в виде таблицы в консоли.

## 5. 1C Experience (Визуальный конструктор сущностей)
**Оценка:** Сложно.
**Реализация:** Система схем. Пользователь через UI собирает "модель" (добавляет поля: Имя [str], Фракция [link], Уровень [int]). Это сохраняется как мета-JSON. На основе этого мета-JSON динамически генерируется форма ввода (Dynamic Forms). Как в Strapi или Notion. Vue с этим справляется отлично через `<component :is="...">`.

## 6. Каркас произведения (AI Agents planning)
**Оценка:** Средне.
**Реализация:** Канбан-доска или Outliner (как в WorkFlowy). По сути, иерархический список чек-листов, привязанный к конкретной главе.

## 7. Zen Mode
**Оценка:** Легко.
**Реализация:** Кнопка Fullscreen API браузера + CSS-класс на `body`, который скрывает все тулбары и оставляет только узкую колонку текста посередине и черный фон.

## 8. Граф связей
**Оценка:** Зависит от объема.
**Реализация:** Библиотеки `Vis.js`, `D3.js` или `Cytoscape`. Rust-бекэнд собирает все связи (кто кого знает, кто в какой фракции) и отправляет на фронт ноды (nodes) и грани (edges) для отрисовки.

## 9. Full проверка орфографии AI
**Оценка:** Требует мощностей.
**Реализация:** Если оффлайн - нужна локальная LLM или специализированная модель (напр. LanguageTool) запущенная через Rust. API - легко, но зависит от интернета.

## 10. Умное AI автодополнение с доступом к БД (RAG)
**Оценка:** Инновационно.
**Реализация:** Локальный RAG (Retrieval-Augmented Generation). Когда пользователь пишет "Король открыл дверь и увидел...", модуль на Rust делает быстрый векторный или полнотекстовый поиск по БД, понимает, что "Король" сейчас в "Замке", рядом с ним "Советник", и скармливает этот контекст небольшому локальному трансформеру (через ONNX / Llama.cpp в Tauri), который выдает предсказание.

## 11. Мобильная версия с синхронизацией по QR (Seamless Handoff)
**Оценка:** Сложно.
**Реализация:** Tauri (Rust) запускает локальный HTTP/WebSocket сервер. Телефон и комп в одном Wi-Fi. Сканируешь QR (в нем локальный IP компа + токен). Телефон открывает PWA-приложение, которое подключается к компу по WebSocket. Любая буква, напечатанная на телефоне, мгновенно улетает на комп и сохраняется в БД.

## 12. Интерфейс Obsidian (Zettelkasten)
**Оценка:** Синергия с п.2.
**Реализация:** Использование `[[link]]` внутри TipTap редактора. Автоматически создает сущность-заметку (shadow note), если ее еще нет. 

## 13. Склонение названий
**Оценка:** Средне.
**Реализация:** Библиотека вроде `az` (для JS) или `padeg`. Хранить в БД как базовое имя + маппинг пользовательских исключений. В Markdown можно сделать свой синтаксис `{{Имя_Персонажа|дательный}}`.

## 14. Окно для RolePlay (RP / 18+) чата с персонажами
**Оценка:** Архитектурно очень легко, синергия колоссальная.
**Реализация:** Чат-интерфейс на Vue делается элементарно (Flexbox + список сообщений). Сильная сторона в том, что благодаря локальным LLM (запущенным через Tauri/llama.cpp), у тебя нет никакой цензуры — любые скачанные uncensored модели (типа Dolphin или специальных RP-весов) работают оффлайн и позволяют 18+ контент без банов и ограничений API.
**Главная киллер-фича:** Так как RP встроено в твою Wiki-базу, тебе не нужно руками писать "Карточки персонажей" (как в SillyTavern). Ты просто открываешь чат с персонажем, а Rust-бэкэнд сам вытягивает из БД его характер, отношения, инвентарь и текущую локацию, подавая это в System Prompt. Диалог можно сразу сохранять как "Черновик главы".

---
**Итоги по стеку:**
Такое приложение **невозможно** построить на ванильном HTML/JS. 
Нужен жесткий, типизированный каркас: `Tauri + Vue 3 (Composition API) + Pinia + Vue Router + TipTap (редактор) + Tailwind/Vanilla CSS`. 
Стейт-менеджмент будет сердцем всего этого.
