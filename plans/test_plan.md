# Testing Strategy: 100% Coverage for Settings

Цель данного плана — выстроить надежную инфраструктуру тестирования в monorepo (с использованием **Turborepo**), чтобы покрыть 100% логики работы с настройками (UI, Service, Backend) и гарантировать, что ни одно обновление больше не сломает их применение.

## Инфраструктура и Инструменты (Turborepo)

Для управления тестами в monorepo будет использоваться **Turborepo**:
1. **Обновление `turbo.json`**: Добавление задачи `"test"`, которая будет зависеть от `"build"` (или выполняться параллельно), с кэшированием результатов. Это позволит запускать `pnpm test` в корне, и Turbo сам запустит тесты только в тех пакетах, где поменялся код.
2. **Frontend-тесты**: `Vitest` + `Vue Test Utils` + `@vue/test-utils` + `@vitest/coverage-v8` (для отслеживания заветных 100% покрытия).
3. **Backend-тесты**: Нативный `cargo test` в Rust-воркспейсе.

## Что именно мы будем тестировать (Proposed Changes)

### 1. Слой Сервиса: `settings.service.ts` (Vitest)
Это ядро логики, здесь требуется **абсолютное покрытие (100% Branches/Lines)**.
* **Изоляция:** Мы замокаем `window.__TAURI__`, `localStorage` и `document`.
* **Тесты загрузки (loadSettings):**
  * Загрузка из Tauri: успешная и с ошибкой (проверка перехода на fallback).
  * Загрузка из `localStorage`: парсинг валидного JSON и отлов `SyntaxError` при битом JSON.
  * Проверка `deepMerge`: если в сохраненном конфиге нет ключа `background`, он должен взяться из дефолтного.
* **Тесты сохранения (saveSettings):**
  * Проверка мгновенного применения (вызовы `applySettings` и `applyLocale`).
  * Проверка debounce-логики (сохранение откладывается на 300мс, кроме флага `immediate`).
  * Проверка вызова IPC-команды `save_settings` к Rust-бэкенду.
* **Бизнес-логика (applyQualityLevel):**
  * Математические проверки: если передать уровень 20%, то `blur` должен стать `4px`, а анимации отключиться.
* **DOM Мутации (applySettings / applyBackground):**
  * Проверка того, что сервис действительно делает вызовы `root.style.setProperty('--bg-base', ...)` с правильными значениями.
  * Проверка защитного `try/catch` при попытке загрузить локальный файл через несуществующий API Tauri в режиме браузера.

### 2. Слой UI: `Settings.vue` (Vue Test Utils + Vitest)
Здесь мы проверяем пользовательский интерфейс и связки данных.
* **Рендеринг:**
  * Проверка, что компонент рендерится без ошибок.
  * Симуляция смены категории (например, клик по "Производительность" скрывает остальные группы).
* **Реактивность и биндинги:**
  * Поиск `<input type="checkbox">` для настройки "Компактный список", симуляция клика. Проверка, что `settings.value.cards.compactList` поменял значение.
  * Симуляция ввода в `<input type="range">` для ползунка качества — проверка, что вызывается `applyQuality()`.
* **Диалоги и Файлы (pickBackgroundFile):**
  * Мок функции `open` из `@tauri-apps/plugin-dialog` и мок `readFile`.
  * Передача фейкового пути файла и проверка, что компонент правильно определяет тип (картинка/видео) и вызывает Rust-команду `upload_photo` перед сохранением.

### 3. Слой Бэкенда (Rust: Cargo Test)
Даже если фронтенд работает идеально, бэкенд может не сохранить данные.
* **Логика `system.rs` (tauri-shell):**
  * **Тест `save_settings`:** Инициализация `in-memory` базы данных SurrealDB, вызов команды с валидным JSON, проверка успешного ответа базы.
  * **Тест `load_settings`:** Прямая запись конфига в базу, вызов команды, проверка соответствия возвращенной структуры.
  * **Ошибки:** Отправка некорректных данных (например, если фронтенд прислал мусор) и проверка корректной обработки (возврат `Result::Err`).

## Verification Plan (План проверки)

1. **Метрики:** После написания тестов будет запущен скрипт `vitest run --coverage`. Я предоставлю вам отчет, доказывающий, что файлы `settings.service.ts` и `Settings.vue` имеют 100% покрытие по строкам (Lines) и ветвлениям (Branches).
2. **CI/CD готовность:** Команда `pnpm turbo run test` будет корректно запускать тесты как для `spa`, так и для `components`.
3. **Отсутствие регрессий:** Тесты мгновенно покажут падение, если в будущем кто-то попытается переименовать ключи в `AppSettings` или сломает вызовы Tauri API.
