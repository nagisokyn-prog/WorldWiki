# План миграции интерфейса (SPA + Glassmorphism + Foundation for AI)

Этот план описывает глобальный переход от текущей MPA-архитектуры (множество `.html` файлов со строковыми Vue-шаблонами) к полноценному SPA (Single Page Application) на базе Vue 3 с компонентным подходом. Рефакторинг закладывает масштабируемый фундамент для сложного оконного интерфейса (VS Code Style) и будущей интеграции ИИ-агентов.

## 1. Анализ текущей реализации и дизайн-кода
- **Дыхание интерфейса**: Анимации push/pull навигации (класс `.interactive-el`), меняющие `scale` элемента при `:hover` и `:active`.
- **Стекло/Glassmorphism**: Прозрачные панели (`rgba`), интенсивный `backdrop-filter: blur()`, неоновые свечения на заднем фоне (`.bg-glow`).
- **Сложный UX (Xbox колесо)**: Крутящиеся селекторы с расчетом дистанции (`diff`) от активного элемента, которые меняют масштаб и прозрачность строк. Требуют переноса в изолированные компоненты.

---

## 2. Экстракция в Vue-компоненты (Декомпозиция)

Все UI-элементы переносятся в `src/js/components/` в виде полноценных `.vue` файлов (SFC - Single File Components с `<script setup>`):

### Базовые UI-элементы (Атомы/Молекулы)
1. **InteractiveButton.vue** (`.btn.interactive-el`) - Базовая кнопка "с дыханием".
2. **GlassCard.vue** (`.glass-card-container`) - Универсальный стеклянный контейнер с внутренним блюром.
3. **XboxWheelSelect.vue** (`.calendar-wheel`) - Универсальное колесо выбора (отвязанное от календаря), замена стандартным `<select>`.
4. **ActivityIcon.vue** (`.activity-icon`) - Иконка левого сайдбара с индикаторами.

### Структурные макеты (Организмы)
5. **AppSidebar.vue** - Главный сайдбар со списком сущностей, поиском и навигацией.
6. **EditorTabs.vue** - Вкладки открытых документов (с индикацией несохраненных данных).
7. **AppBottomPanel.vue** - Выдвижная консоль и статистика (с ресайзом).
8. **CommandPalette.vue** - Глобальный поиск (VS Code style popup).

## 3. Инженерный план рефакторинга: От MPA к SPA

Для поддержки сложной бизнес-логики и многооконности (Сплит-скрины) архитектура должна стать одностраничной. 

### Этап 1: Переходный сетап (Vite + Vue SFC)
- Настроить Vite для компиляции `*.vue` файлов.
- Удалить глобальное подключение `<script src="vue.global.js">` из HTML, заменить на модульный импорт `import { createApp } from 'vue'`.
- Оставить один `index.html` в качестве единой точки входа (заменить им старый `app.html`).
- Подключить `new-ui-theme.css` как глобальную точку стилей.

### Этап 2: Стейт-менеджмент (Pinia)
Система VS-Code окон требует глобального состояния. Пишем хранилища (stores):
- **`useEditorStore`**: Управляет открытыми вкладками, несохраненными изменениями, фокусом (какая вкладка активна в каком сплите).
- **`useAppStore`**: Глобальные флаги UI (открыт/закрыт сайдбар, тема, высота консоли).

### Этап 3: Роутинг (Vue Router)
Убираем переходы между физическими HTML-страницами (`ui_menu.html`, `chapters.html`, `settings.html`). Заменяем их на:
- `<router-view>` в корневом компоненте `App.vue`.
- Плавные `<Transition>` между страницами (чтобы сохранить "нативный" feel).
- Внедрение окна `RolePlayChat.vue` как часть дерева роутинга или оверлея.

### Этап 4: Разделение логики и представления в Редакторе
Текущий редактор тесно связан с UI.
- Подготовка к переходу на блочный AST-редактор (TipTap).
- Подготовка логики отдачи данных из БД в предсказуемом JSON формате (вместо сырого Markdown).

## 4. Подготовка площадки под ИИ (Research Base)

Архитектурные изменения фронтенда должны учитывать будущие нагрузки от локальных ИИ-агентов:
- **Асинхронные потоки (Streaming)**: Поддержка стриминга токенов с бекенда (Tauri) во фронтенд для автодополнения (поштучное появление текста в окне редактора или RP-чате без лагов ввода).
- **Семантическая разметка компонентов**: Все значимые текстовые узлы должны иметь четкие ID и типы (мысль, диалог), чтобы RAG-система могла парсить DOM/состояние в фоне, не блокируя UI-поток (Event Loop).
- **Локальная очередь (Task Queue) в Pinia**: Очередь фоновых задач для агентов (например, "Идет анализ главы комиссией агентов...").

## 5. Итог: Что за чем делаем
1. Локально поднимаем Vue + Pinia + Vue Router на сборке Vite.
2. Верстаем Layout из компонентов (Сайдбар, Табы, Консоль).
3. Перетягиваем логику списка сущностей и редактора в новый стор.
4. Вычищаем старые HTML шаблоны.
