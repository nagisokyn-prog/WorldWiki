## 🔴 1. `scalar.rs` — **самое** **опасное** **место**

**1.1. Переполнение `i64` при восстановлении `t_abs`.**

Ты **пишешь**: `t_abs = world_day * planet.ticks_per_day + day_tick`. **Если** `world_day` **~** `i64::MAX / ticks_per_day`, **то** **умножение** **переполнится**. **С** `debug_assertions` **будет** **паника**. **В** **релизе** — **undefined** **поведение** (Rust **сейчас** **делает** **wrapping**, **но** **это** **UB** **по** **спеке**).

**Решение**: **все** **арифметические** **операции** **с** `world_day` **и** `ticks_per_day` **—** **через** `i128`**.** **У** **тебя** **уже** **есть** `proof_scalar_reconstruction`. **Убедись**, **что** **он** **включает** **проверку** **границ** `i64`. **Добавь** `checked_mul` **и** `checked_add` **с** **явной** **ошибкой** `ScalarOverflow`.

**1.2. `planet_id` **—** **это** `String`. **В** **горячем** **пути** **ты** **делаешь** **hash** **и** **сравнение**.**

**Сравнение** **строк** **в** **каждом** **вызове** `local_moment` **—** **это** **дорого**. **Это** **не** **критично** **для** **корректности**, **но** **плохо** **для** **производительности** **при** **массовых** **расчётах**. **Решение**: **ввести** `PlanetId(u32)` **и** **мапить** **через** **интернер**.

**1.3. `day_start_offset` **—** **это** `i64`. **Что** **если** **он** **не** **влезает** **в** `[0, ticks_per_day)`?**

**Спецификация** **говорит**: `|day_start_offset_ticks| < planet.ticks_per_day`. **Но** **это** **только** **инвариант**. **Где** **он** **проверяется**? **При** **валидации** **календаря**? **При** **каждом** **вызове**? **Если** **автор** **через** **UI** **введёт** `day_start_offset_ticks = 10^18`, **что** **будет**? **Решение**: **добавь** `proof_day_start_offset_bounded` **и** **нормализуй** **через** `rem_euclid`.

**1.4. `t_abs` **как** `i64` **—** **это** **±106** **млн** **лет** **при** **наносекундной** **точности**. **Что** **если** **автор** **пишет** **про** **вселенную** **возрастом** **13.8** **млрд** **лет**?**

## 🔴 2. `dial.rs` — **скрытые** **баги** **в** **каскадном** **квантовании**

**2.1. `subdivisions = 0` **—** **деление** **на** **ноль**. **Ты** **проверяешь**?** 

**В** **спецификации** **написано**: `unit.subdivisions > 0`. **Где** **валидация**? **Добавь** `proof_dial_subdivisions_nonzero`. **И** **проверку** **при** **создании** `DialHierarchy`.

**2.2. Каскадное** **квантование** **—** **это** **умножение** `subdivisions` **по** **цепочке**. **Что** **если** `24 * 60 * 60 * 1000 = 86 400 000` **влезет**, **а** **ещё** **одна** **единица** **—** **уже** **нет**?**

**У** **тебя** **проверка** `ticks_per_day >= dial_ticks_per_day`. **Но** `dial_ticks_per_day` **сам** **может** **переполниться** **при** **подсчёте**. **Решение**: **считай** `dial_ticks_per_day` **в** `i128` **с** `checked_mul`. **Если** **переполнение** — **отказ** **валидации**.

**2.3. Биективность** **каскадного** **квантования** **—** **это** **НЕ** **биективность**, **если** `ticks_per_day % dial_ticks_per_day != 0`.**

**Пример**: `ticks_per_day = 100`, `dial_ticks_per_day = 3`. **Тогда** `units_to_day_tick(day_tick_to_units(t))` **может** **не** **вернуть** `t`. **Ты** **используешь** `ceil` **при** **прямом** **и** `floor` **при** **обратном** — **это** **создаёт** **«мёртвые** **зоны»**. **Пользователь** **введёт** «12:34:56», **система** **сохранит** **один** `t`, **а** **при** **обратном** **чтении** **выдаст** «12:34:55». **Решение**: **либо** **требуй** `ticks_per_day % dial_ticks_per_day == 0` **как** **инвариант** **(жёстко)**, **либо** **документируй** **потерю** **точности** **и** **показывай** **её** **в** **UI**.

**2.4. Что** **если** `units` **содержит** **единицы** **с** **одинаковыми** **именами**?**

**«Стража, Стража, Стража»** — **это** **валидно** **математически**, **но** **бред** **в** **UI**. **Добавь** **проверку** **уникальности** **имён**.

**2.5. Пустой** `units` **и** **пустой** **список** **имён** **дней** **недели** — **это** **разные** **случаи**.

**Пустой** `units` **означает** «время** **внутри** **суток** **не** **квантуется**». **Пустой** `weekdays` — **деление** **на** **ноль** **в** `rem_euclid`. **Убедись**, **что** **валидация** **ловит** **пустой** `weekdays`.

## 🔴 3. `leap.rs` — **самый** **сложный** **модуль**. **Тут** **ты** **будешь** **ловить** **баги** **годами**

**3.1. `divisor_c < 0` **—** **ты** **обрабатываешь**?**

**Формула** `floor_div(a*Y + b, c)` **с** **отрицательным** `c` **даёт** **неверный** **результат** **даже** **с** `div_euclid`. **Проверь**: `proof_leap_divisor_positive` — **все** `c_i > 0`.

**3.2. `days_offset` **—** **это** `i32`. **Что** **если** **автор** **введёт** **отрицательный** **offset**?**

**«Високосный** **год** **на** **один** **день** **короче»** — **это** **валидная** **идея**. **Но** **твоя** **формула** `base + D * is_leap(Y)` **не** **сломается**. **А** **вот** `days_up_to_year` **может** **дать** **немонотонность**, **если** `D < 0` **и** `is_leap` **скачет**. **Добавь** **инвариант**: `D >= 0` **или** **докажи** **монотонность** **для** **отрицательного** `D`.

**3.3. `LeapTarget::InMonth { target_month }` **с** `target_month >= months.len()`.**

**Паника** **при** **обращении** **к** `months[m]`. **Проверка** **должна** **быть** **в** **валидации** `CalendarData` **и** **в** **Kani**. **Добавь** `proof_leap_target_month_bounded`.

**3.4. LCM** **периода** **гармоник** **может** **быть** **астрономическим**.

**Пример**: **автор** **задал** **гармоники** **с** `c = [4, 100, 400]` — **LCM = 400**. **Ок**. **Но** **если** `c = [7, 19, 33, 100, 400]` — **LCM = 7 * 19 * 33 * 100 * 400 = 175 560 000**. **Проверка** `validate_harmonics_step` **будет** **итерировать** **175** **миллионов** **итераций**. **Решение**: 
- **Ограничь** **LCM** **сверху** (например, `10^7`).
- **Или** **проверяй** **шаг** **аналитически** (по** **структуре** **гармоник**), **а** **не** **перебором**.
- **Или** **кэшируй** **результат** **валидации**.

**3.5. Формула** `F(Y) = sum(w_i * floor_div(a_i * Y + b_i, c_i))` **—** **это** **НЕ** **всегда** **шаг** **{0, 1}**.**

**Пример**: `w = [+1, +1]`, `a = [1, 1]`, `c = [2, 3]`. **Тогда** `F(0) = 0`, `F(1) = 0 + 0 = 0`, `F(2) = 1 + 0 = 1`, `F(3) = 1 + 1 = 2`. **Шаг** `F(3) - F(2) = 1`. **Ок**. **А** **если** `w = [+1, -1]`, `a = [1, 1]`, `c = [2, 3]`? **F(2) = 1 - 0 = 1**, **F(3) = 1 - 1 = 0**. **Шаг** `= -1`. **Отрицательный**! **Твоя** **проверка** **должна** **ловить** **это** **и** **отказывать**. **У** **тебя** **в** **Kani** **есть** `proof_gregorian_leap_step_bounded`, **но** **нет** `proof_negative_weight_step_bounded` **для** **общего** **случая**.

**3.6. Формула** `days_up_to_year(Y)` **считает** **дни** **от** **начала** **года** **1**.** **А** **если** **эпоха** **календаря** **—** **не** **год** **1**?**

**Ты** **пишешь**: `((Y - 1) * base + D * (F(Y-1) - F(0)))`. **При** `Y = 0`: `(−1) * base + D * (F(-1) − F(0))`. **Числитель** **отрицательный**. **Знаменатель** — **ок**. **Это** **работает**, **но** **проверь** **на** **Kani** **для** **Y** **в** **диапазоне** `[-10^6, 10^6]`.

**3.7. Что** **если** **правило** **високосности** **содержит** **дубликаты** **гармоник**?

**`[+1/4, +1/4]`** — **это** **то** **же** **самое**, **что** `+2/4` **=** `+1/2`. **Шаг** **будет** **0** **или** **2**. **Твой** **валидатор** **откажет**? **Правильно** **откажет**. **Но** **надо** **явно** **сказать** **автору**: «Дубликаты** **не** **поддерживаются**».

**3.8. `proof_i128_overflow_free` **—** **что** **именно** **он** **доказывает**?**

**Ты** **пишешь**: «отсутствие** **целочисленных** **переполнений** **в** **128-битных** **расчетах** **дней** **до** **года»**. **Но** `Y - 1` **может** **быть** `i64::MIN`, **умножение** `Y * base` — **в** `i128` **не** **переполнится**, **но** `Y * base * Q_den` **в** `year_finder` **может** **уже** **не** **влезть**. **Проверь** **границы** **явно**.

18. `proof_age_first_month_zero_length` — рождение в первом месяце, если он нулевой длины.
