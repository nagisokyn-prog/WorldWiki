# План 2: Схема Данных и SurrealDB

## Цели и Задачи
- Спроектировать хранение иерархических чатов (ветвление как в Git).
- Спроектировать систему хранения прав (Auto-Approval).

## 1. Структура Чата и Сообщений
Для поддержки ветвлений мы уходим от парадигмы "чат = массив сообщений".
В SurrealDB будут таблицы `ai_chats` и `ai_messages`.

**Таблица `ai_messages`:**
- `id`: Уникальный ID сообщения.
- `chat_id`: К какому логическому чату (дереву) принадлежит.
- `parent_msg_id`: ID предыдущего сообщения (формирует дерево/ветку). У корневого сообщения — `null`.
- `role`: `user`, `assistant`, `tool_call`, `tool_result`, `system`.
- `content`: Markdown текст (или JSON для tool calls).
- `context_attachments`: Массив прикреплённых контекстов (ID сущностей, глав, томов), которые выбрал юзер через "+".
- `edited_by_user`: (bool) Отредактировано ли сообщение ИИ пользователем.

**Таблица `ai_chats` (Логическое дерево):**
- `id`: Уникальный ID дерева.
- `title`: Автоматически сгенерированное название.
- `parent_chat_id`: Если ветка логически создана от другого чата (для UI папок/групп).
- `leaf_msg_id`: ID последнего активного сообщения в этой ветке. При отрисовке чата мы берём `leaf_msg_id` и идём вверх по `parent_msg_id` до корня, собирая линейную историю.
- `tags`: Массив тегов.

## 2. Хранение настроек Auto-Approval (Автоодобрение)
Хранится в таблице `auto_approval_settings`.
```json
{
  "id": "auto_approval_settings:global",
  "enabled": true,
  "categories": {
    "read": true,
    "edit_entities": false,
    "edit_content": false,
    "edit_relations": false,
    "edit_calendar": false,
    "analyze": true
  },
  "allowlist": {
    "entity_types": ["character", "location"],
    "rel_types": ["дружба"],
    "paths": ["project/volume_1"]
  },
  "denylist": {
    "entity_types": ["organization"],
    "rel_types": ["вражда"],
    "paths": ["project/volume_3"]
  }
}
```

## 3. Редактирование ответа ИИ пользователем
- Когда пользователь редактирует ответ ИИ (например, чтобы поправить его логику), создаётся новое сообщение (новый `ai_message` со ссылкой на тот же `parent_msg_id`), где роль остаётся `assistant`, но `edited_by_user: true`.
- Чат (или новая ветка) обновляет свой `leaf_msg_id` на это новое сообщение. 
- Агенту при следующем запросе передаётся именно этот изменённый ответ, чтобы в памяти ИИ осталась исправленная версия. Для ИИ это будет выглядеть так, как будто это он сам сгенерировал правильный ответ.
