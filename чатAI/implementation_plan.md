# Внедрение режимов AI агента (Modes) и динамических инструментов

Цель: реализовать полноценную систему "Режимов" для ИИ-агента, позволяющую ему переключаться между ролями, такими как "Собеседник", "Редактор" и "Аналитик", каждая из которых будет иметь свой собственный системный промпт (роль) и свой набор доступных инструментов (tools).

## Требуется ревью

> [!IMPORTANT]
> Это крупное архитектурное изменение, затрагивающее как фронтенд (Vue), так и бэкенд (Rust/SurrealDB). Ниже обновлённый план, учитывающий сложную структуру сущностей (таймлайны, выпадающие списки, связи). Если всё верно — подтвердите, и мы перейдём к написанию кода!

## Решённые архитектурные вопросы

1. **Хранение режимов**: Решено использовать таблицу `ai_modes` в базе SurrealDB. Это упростит синхронизацию и работу с интерфейсом.
2. **Аналитические инструменты**: На первой итерации аналитические функции будут возвращать базовые структурированные данные без сложных многопроходных запросов или заглушек.

#### [NEW] `AI Ghost Text` (Автодополнение в Tiptap)
Для редактора глав добавим функцию автодополнения (как GitHub Copilot). Принцип реализации:
- **ProseMirror Plugin**: Создаём кастомный плагин для Tiptap, который отслеживает паузы в печати (debounce 500-1000мс).
- **Декорации (Decorations)**: Если пришёл ответ от LLM, плагин рендерит "призрачный текст" (серый невыделяемый текст) прямо за курсором с помощью `Decoration.widget` или `Decoration.inline` из ProseMirror.
- **Стриминг или One-Shot**: Контекст до курсора (и, возможно, после) отправляется к LLM, ответ возвращается и рендерится.
- **Перехват клавиши Tab**: Плагин биндит обработчик на `Tab` (или `Right Arrow`). Если есть активная декорация призрачного текста, нажатие `Tab` вставляет этот текст в реальный документ (`editor.chain().insertContent(suggestion).run()`) и удаляет декорацию. Если декорации нет, `Tab` работает как обычно.

## План проверки (Verification Plan)

### Автоматизированное/Ручное тестирование
- **Валидация схемы**: Убедиться, что таблица `ai_modes` создаётся и работает.
- **Интерфейс режимов**: Интерфейс должен соответствовать Roo Code и сохранять конфигурации в БД.
- **Тест редактирования сущности (Сложный)**:
  1. В режиме "Редактор" попросить ИИ изменить статус персонажа и связать его с другим.
  2. ИИ должен вызвать `get_entity_schema`, понять доступные статусы.
  3. ИИ должен вызвать `search_entities`, чтобы получить `RecordId` для связи.
  4. ИИ должен вызвать `update_entity` с частичным JSON.
  5. UI WorldWiki не должен сломаться, все данные должны отобразиться корректно.
