15) Система разрешений и уровней автоодобрения (Auto-Approval)

WorldWiki использует систему разрешений, аналогичную Roo Code, но адаптированную для писательских задач и работы с литературными сущностями.
		1.1. Глобальный переключатель (Master Switch)
		Пользователь может включить или отключить автоодобрение для всех действий.
		- При выключенном переключателе ЛЮБОЕ действие модели требует подтверждения пользователя.
		- Переключатель доступен в настройках профиля агента.

		1.2. Категории разрешений (Группы инструментов)
		Автоодобрение настраивается отдельно для каждой категории действий.

		| Категория | Что контролирует | Риск | По умолчанию |
		|-----------|------------------|------|--------------|
		| read | Поиск сущностей, чтение глав, получение связей, просмотр календарей | Низкий (только чтение) | Включено |
		| edit_entities | Создание, изменение и удаление сущностей (персонажи, организации и т.д.) | Высокий | Отключено |
		| edit_content | Изменение текста глав, создание/удаление томов и арок | Высокий | Отключено |
		| edit_relations | Создание, изменение и удаление связей между сущностями | Средний | Отключено |
		| edit_calendar | Изменение календаря, эпох, праздников, сезонов | Средний | Отключено |
		| analyze | Запуск аналитических отчётов, поиск противоречий, построение графов | Низкий | Включено |

		1.3. Уровни автоодобрения (Presets)
		Пользователь может выбрать один из трёх предустановленных профилей:

		A) Безопасный (Safe)
		   - read: Включено
		   - analyze: Включено
		   - Все остальные категории: Отключено
		   - Описание: Модель только читает и анализирует. Изменения запрещены.

		B) Сбалансированный (Balanced)
		   - read: Включено
		   - analyze: Включено
		   - edit_entities: Включено (только создание)
		   - edit_relations: Включено (только создание)
		   - edit_content: Отключено
		   - edit_calendar: Отключено
		   - Описание: Модель может создавать новое, но не удалять и не изменять существующее.

		C) Экспертный (Expert)
		   - Все категории (кроме execute): Включено
		   - Описание: Модель может всё, кроме доступа к системе. Только для опытных пользователей.

16) Гранулярный контроль (Allowlist / Denylist)

	Пользователь может настроить автоодобрение на уровне конкретных действий.

	16.1. По содержимому сущностей (Entity Types)
	Пользователь указывает, какие типы сущностей (type_key из entity_schemas) можно создавать/редактировать без подтверждения.

	Пример:
	  Allowlist:
		- character
		- location
	  
	  Denylist:
		- organization
		- state

	Если тип сущности в Denylist, её создание ВСЕГДА требует подтверждения, даже если категория edit_entities включена.

	16.2. По типам связей (Relation Types)
	Пользователь указывает, какие типы связей (rel_key из relation_schemas) можно создавать без подтверждения.

	Пример:
	  Allowlist:
		- дружба
		- союз

	  Denylist:
		- вражда
		- предательство

	16.3. По частям проекта (Paths)
	Пользователь может указать конкретные пути (том/арка/глава), изменения в которых не требуют подтверждения.

	Пример:
	  Allowlist:
		- project/мой_проект/volume_1
		- project/мой_проект/volume_2/arc_3

	  Denylist:
		- project/мой_проект/volume_3 (критическая арка — всё требует подтверждения)

	16.4. Приоритеты
		1. Denylist имеет приоритет над Allowlist. Если тип сущности есть в обоих списках — действие НЕ будет автоодобрено.
		2. Категории имеют приоритет над гаранулярными настройками. Если категория edit_entities отключена — никакие Allowlist не помогут.
		3. Удаление (delete) НИКОГДА не автоодобряется, даже если тип сущности в Allowlist.

	3.5. Хранение настроек
	Настройки хранятся в SurrealDB в таблице auto_approval_settings:
		- enabled (bool) — глобальный переключатель
		- categories (object) — { read: true, edit_entities: false, ... }
		- allowlist (object) — { entity_types: ["character"], rel_types: ["дружба"], paths: ["project/volume_1"] }
		- denylist (object) — { entity_types: ["organization"], rel_types: ["вражда"], paths: ["project/volume_3"] }
