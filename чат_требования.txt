1) виджет чата должен хранить несколько чатов, используя для отображения списка переделанный ChapterTree.vue
2) должен быть поиск по чатам
3) каждому чату должен прикрепляться тег
4) для каждого чата ИИ должен создавать название
5) для сообщений пользователя каждого чата должна быть возможность изменения сообщения, с сохранением предыдущего сообщения, к которому пользователь может вернуться через стрелочки навигации "<>"
6) для отображения сообщений должен использоваться tiptap, который должен поддерживать markdown, md и latex отображение (пользователь пишет в окне для сообщения, отправляет и после отправления всё парститься)
7) ИИ передаётся не весь чат целиком со всеми переписываниями, а только то, что юзер видит на экране
8) должно быть реализовано git ветвление:
	а) пользователь ушёл от темы на n-ное к-во сообщений возвращается к месту от которого начался офтпик,  нажимает на кнопку вида:
		<svg stroke="currentColor" fill="none" stroke-width="2" viewBox="0 0 24 24" stroke-linecap="round" stroke-linejoin="round" height="16" width="16" xmlns="http://www.w3.org/2000/svg"><path d="M7 18m-2 0a2 2 0 1 0 4 0a2 2 0 1 0 -4 0"></path><path d="M7 6m-2 0a2 2 0 1 0 4 0a2 2 0 1 0 -4 0"></path><path d="M17 6m-2 0a2 2 0 1 0 4 0a2 2 0 1 0 -4 0"></path><path d="M7 8l0 8"></path><path d="M9 18h6a2 2 0 0 0 2 -2v-5"></path><path d="M14 14l3 -3l3 3"></path></svg>
		и после нажатия этой кнопки ему создаётся новый чат, куда копируются все сообщения включая то, на котором он нажал кнопку ветвлеления
	б) пользвателя автоматически переносит в новый чат
	в) этот новый чат спускается на уровень ниже создавая логический иерархический вид:
				Иерархическая модель представляет базу данных как упорядоченный набор деревьев (лесов). Структура состоит из сегментов (записей), связанных физическими указателями по схеме «один родитель — много потомков» (1:M).
				Основные правила структуры:
				?	Существует единственный корневой сегмент, не имеющий родителей.
				?	Каждый подчиненный сегмент имеет ровно одного родителя.
				?	Доступ к любому подчиненному сегменту возможен только через его родителя (сверху вниз).
				Пример наполнения модели:
				[Кафедра: ИУК5] (Корень)
				   |-- [Группа: ИУК5-41] (Потомок 1-го уровня)
				   |      |-- [Студент: Иванов] (Потомок 2-го уровня)
				   |      |-- [Студент: Петров]
				   |-- [Группа: ИУК5-42]
						  |-- [Студент: Сидоров]
	г) при этом через drag on drop перетаскивание должна быть реализована смена родителя и поотомка, чтобы оффтопики не стали родителями и пользователь не искал долго нужную ветку
9) в чате пользователь должен иметь возможность включить и отключить функции "Глубокое мышление" и "Поиск в интернете"
10) в чате пользователь должен иметь возможность отредактировать ответ ИИ, с указанием почему ИИ ошибся
11) в чате должна быть реализована возможность выбора Томов, Арок, Глав и Сущностей для обсуждения через мультивыбор:
	сверху в правом углу пользователь нажимает на кнопку "+"
	ему выпадает список первого уровня:
		Том (весь том/тома целиком будет анализироваться)
		Арка (вся арка/арки целиком будет анализироваться)
		Глава (вся глава/главы целиком будет анализироваться)
		Сущность
	При выборе любого из пунктов (кроме Сущность) пользователь попадает в списов второго уровня, где уже выбирает то, что ему нужно (Том/Тома, Арку/Арки, Главу/Главы)
	Если пользователь выбрал Сущность, то он попадает в список второго уровня, где выбирает Тип сущности
	После выбора Типа Сущности пользователь попадает в список третьего уровня, где выбирает саму Сущность/Сущности
	При этом после выбора пользователь должен иметь возможность вернуться к предыдущему уровню, чтобы чтобы продолжить выбирать
	При этом пользователь должен иметь возможность найти то, что его интересует через "поисковик"
